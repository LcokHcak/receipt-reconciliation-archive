## 3. OCR 审核字段(审核中心 · 字段审核 Tab)

> 字段名后缀 `Final` 是「人工确认后的最终值」(OCR 出初值,人改成 Final)。

### 护照类
| 界面标签 | 字段 | 含义 / 判断 |
|---|---|---|
| 英文名 | extractedNameFinal | 护照上的英文姓名,核对拼写 |
| 护照号 | passportNoFinal | 护照号码,核对位数/字母 |
| 中文签字名 | chineseNameFinal | 中文签字用名,签字凭证用 |

### 小票类
| 界面标签 | 字段 | 含义 / 判断 |
|---|---|---|
| 免税店 | receiptStoreFinal | **三选一**:LOTTE(乐天)/ THE SHILLA(新罗)/ SHILLA IPARK(新罗 IPARK)。保存为后端标准枚举 |
| 小票号 | receiptNoFinal | 小票编号,账单匹配的关键键 |
| 团号 | groupNoFinal | 旅行团号,团号匹配的关键键 |
| 购买日期 | purchaseDateFinal | 购买日。**决定入哪个月**(按购买日拆月) |
| 出境日期 | departureDateFinal | 离境日,核对是否在有效窗口内 |

> 黄标 = OCR 置信度低,**重点人工核**。点图上定位框可跳到对应字段。

## 4. 日度台账 / 异常补救(日常工作 → 异常补救)

| 字段 | 含义 |
|---|---|
| 姓名 name | 客人姓名(可改正) |
| 护照号 passportNo | 护照号(可改正) |
| 团号 tourNo | 团号(可改正) |
| 代理 agent | 代理/导游(可改正);别名对不上会反复不匹配 |
| 模式 modeRaw | 返点模式/归类;**选了模式=确认重新匹配** |

### 团号匹配状态 tour_match_status(决定要不要补救)
| 值 | 意思 |
|---|---|
| matched | 已匹配(正常,不进补救) |
| pending | 待匹配(还没跑) |
| tour_not_found | 找不到这个团号 |
| tour_ambiguous | 团号对应多个,无法唯一确定 |
| agent_mismatch | 团号在、但代理对不上(常见:代理别名缺失) |
| date_out_of_window | 购买日不在团的有效日期窗口内 |
| mode_unresolved | 模式没归类出来 |
| date_missing | 缺购买日 |

> **待补救** = 上面 `matched/pending` 以外那 6 种的行数。

| 桶 | 说明 |
|---|---|
| 乐天首尔 | 乐天(首尔)账单 |
| 乐天釜山 | 乐天(釜山)账单 |

- **模式(mode)**:账单/台账的返点归类(如各免税店模式、品牌活动)。「品牌活动 / 限时活动」会折进对应桶(含负数冲减)。

- **模式归类**:账单模式 → 交付桶的映射,跑匹配前必须**确认**。

## 6. 账单匹配率口径(账单匹配 / 最终核对页)

| 指标 | 算法 | 怎么看 |
|---|---|---|
| 台账匹配率 | matched / 台账行数 | **主指标**。台账是小票级,匹配好可到 100% |
| 账单明细覆盖 | matchedBillRows / 总账单明细行 | **辅助指标**。账单是商品/明细行级,数值天然低,别用它当达标线 |

> 注意:「总账单行 / billCount」是 `store_bill` 的商品明细行,**不是按小票号压缩后的数**。

## 9. 工作台首页三段指标(`/`,数据来自 `GET /api/workbench/overview`)

> 口径定义在 `services/workbench_overview_service.js` 顶部注释,改口径要同步改这里。
> **三段刷新口径(一致化)**:
> - **今日待办 = 实时积压**(当前还没处理完的,随时刷新就是最新,不按天清零);
> - **今日进度 = 按天**(只算「今日新建批次」的吞吐,每天 0 点自然清零);
> - **本月进度 = 按所选月份**(本月进度卡右上角下拉选月,选择会被记住)。
> 「今日」按**业务时区**判定:默认 `Asia/Seoul`(UTC+9),可用环境变量
> `SIGN_BUSINESS_TZ` 覆盖;与服务器系统时区解耦,避免 UTC 0 点误切天。
> 接口返回里 `date`=今日(业务时区)、`timezone`=所用时区、`activeMonth`=本月段实际用的月份。

### 今日待办(实时积压,点数字直达)
| 指标 | 含义 | 来源口径 |
|---|---|---|
| 待预处理 | 已上传、还没识别完 | **全部批次** `queued + processing` |
| 待审核 | 识别完、等人工审 | **全部批次** `classification + fields + signature + finalReview` |
| 待补救 | 团号没匹配上的台账行 | **所选月份**台账 `tour_match_status ∈` 上述 6 种 |

### 今日进度(按天,仅今日新建批次)
| 指标 | 含义 | 来源口径 |
|---|---|---|
| 上传 | **今日**上传文件数 | **今日新建批次** `total` 之和 |
| 已审核 | **今日**通过数 | **今日新建批次** `approved` 之和 |
| 待补救 | 同「今日待办·待补救」 | 同上(实时积压) |
| 完成率 | 今日已审核 ÷ 今日上传 | — |
| 导出文件夹 | **今日**新建档客户数 | 客户库 `listCustomers(所选月)` 里 `createdAt` 是今日的 |

### 本月进度(所选月份,卡片右上角下拉切换;默认最新正式月)
| 指标 | 含义 | 来源 |
|---|---|---|
| 客户 | 该月建档客户数 | 客户库 |
| 已收 | 该月台账行数 | `daily_receipt` |
| 未收 | 该月缺口数 | `missing_receipt` |
| 已核对 | 已匹配台账小票数 | `daily_receipt.bill_match_status='matched'` |
| 人工待核 | 待处理阻塞 | `pending_review` 未结 |
| 核对率 | 已核对 ÷ 已收 | — |

### 首页分离追加字段(2026-07-18,管理员/审核员两版首页)

首页已按身份拆两版:admin/finance 见管理员版(管人),reviewer 见审核员版(干活)。以下为 overview 接口新增段:

| 字段 | 含义 | 口径 |
|---|---|---|
| `today.progress.reviewedToday` | 今日审核(动作口径) | 可见范围内**全部批次**里 `task.reviewedAt` 落在今日(KST)的张数;**与"已审核"(仅今日新建批次的存量)不同**,昨天批次今天审掉的也算 |
| `collectors[].uploadedToday` | 该员今日上传 | 其今日新建批次 `total` 之和 |
| `collectors[].reviewedToday` | 该员今日审核 | 动作口径,同上 |
| `collectors[].errorCount / rephotoCount` | OCR失败 / 待补图 | `counts.error` / `counts.rephoto` 之和 |
| `collectors[].staleCount` | 超时批次数 | 有未收尾任务(含 error/rephoto)且距最后动作超 `SIGN_STALE_BATCH_HOURS`(默认 24h,设 0 关闭) |
| `collectors[].workspaces` | "工作区"列 | 该员批次的 `monthlyWorkspaceKey` 去重降序(月份即工作区,不造分区概念) |
| `alerts.ocrFailed / rephoto / stale / unexported` | 异常提醒四胶囊;管理员 KPI「未清异常」= ocrFailed.count + rephoto.count | `{count, batchIds}`,按操作员可见范围,**存量口径无日期过滤**(历史积压全算,修复/补图后回落);待导出=审完且从未盖导出章。KPI 于 2026-07-20 由「今日异常」改名(存量不许顶「今日」前缀) |
| `today.progress.exportedToday` | 今日导出 KPI(P1) | 今日盖章批次的**当前**完成张数(实时值非导出瞬间快照);任一导出类型(结果表/交付包)都算 |
| 批次 `exportedAt/exportedBy/exportKind` | 导出留痕(P1) | 任一导出成功即盖章,最后一次为准;**盖章后再追加内容不会自动失效**,需重新导出刷新 |
| `me.reviewedToday / rank / rankTotal` | 我的今日审核与排名(P2 已渲染) | 排名按全体 owner 今日审核数降序,只回本人名次(不下发他人明细);今日没审过不显示排名卡 |
| `me.todayEfficiency` | 今日效率(P2) | 张/小时 = 今日审核数 ÷ 首末审核跨度(跨批次同日并集,不足 1 小时按 1 小时);没审过为 null 显示 — |
| `me.month` | 我的数据·本月(P2) | reviewed=本月动作口径;avgPerHour=本月完成 ÷ Σ活跃日工时(同上近似);completionRate/reworkRate=现存批次存量口径,**返工率为重拍近似**(拍板#5);批次被清理后月度数字会缩 |
| (admin/finance 的 `me`) | 全局角色中性空值 | reviewedToday=0/efficiency=null/month=null——"我的"字段不装全体聚合(2026-07-19 评审收口) |
| 批次摘要 `reviewStats` | 完成时间/耗时地基 | `{firstReviewedAt, lastReviewedAt, reviewedByDate}`;完成时间=最后审核动作,耗时=建批→最后审核 |

"已完成批次"判定 = `total>0` 且零未收尾(人工待审+queued/processing+**error+rephoto** 全为 0)。

## 10. 月份状态 / 切换

- 右上角**月份切换器**:切月、创建新月(`2026-06` 或 `demo-2026-06`)。
- **未创建的月份**:进去显示「创建本月」引导卡(不是报错),点一下即建。
- `demo-` 前缀 = 测试月,**不计入正式统计**(界面有「测试」徽标)。
