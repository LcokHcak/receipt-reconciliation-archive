# 审核台字段与状态字典(SOP · 全界面数字/徽章/状态一张表)

> 2026-07-14 整理,对应生产 release-c75377c。
> 目的:界面上每个数字/词到底**什么意思、从哪来、哪些是同一个数**——数字对不上时先查这里,再报障。
> 可直接打印/转发给操作员当 SOP。

---

## 一、审核中心(/review)

### 1. 左栏顶部过滤 chips

| 显示 | 含义 | 怎么算 |
|---|---|---|
| 全部 N | 本批次客户组总数 | 按客户组分组后的组数 |
| 待匹配 N | 有小票还没表态(没点 匹配/无团号/S活动)的组数 | 组内存在 `tourStance` 为空的小票(百货/机场豁免票不算) |
| 待处理 N | 还有图没审完的组数 | 组内存在 未通过且未标重拍 的任务 |
| 需重拍 N | 有图被标了重拍的组数 | 组内存在 `rephotoRequested` 的任务 |
| 已通过 N | 全部图都审完的组数 | 组内任务全部 `reviewed`(含已结算的) |

### 2. 组行(一行一个客户组)

| 元素 | 含义 | 来源 |
|---|---|---|
| **组名** | **代理名**(2026-07-14 起恒显代理,不再跳客人英文名) | 任务上的 `customerAgentName`;老任务无代理字段时回落建档标签 |
| 客户号小徽章 | 区分同一代理下的多个客户 | 客户号(CL2026xxxx-xxx) |
| 时间 | 该组最早上传时间(相对时间,悬停看完整) | 组内任务创建时间 |
| **「下一步」胶囊** | 该组当前最要紧的一件事,**一组只显示一个**,优先级:待匹配 N > 需重拍 N > 待审 N > 结算态 > 已审完 | 悬停显示分解(待匹配x·重拍x·待审x) |

「下一步」胶囊可能出现的词:

| 词 | 意思 | 背后字段 |
|---|---|---|
| 待匹配 N | N 张小票还没表态 | `tourStance` 空 |
| 需重拍 | 有图等重拍上传 | `rephotoRequested` |
| 待审 N | N 张图还没点确认 | 未 `reviewed` |
| 待确认模式 | 结算跑完了,等在面板上点确认渠道模式 | 组级结算状态 `needs_confirm` |
| 待补救 | 结算时团号没命中表/日期问题,进了补救台 | 组级结算状态 `needs_remedy` |
| 已结算 | 结算+确认模式全部完成 | 组级结算状态 `settled` |
| 已审完 | 图全审完但还没走结算 | 全 `reviewed` 且无结算态 |

### 3. 任务行(组展开后的每张图)

| 词 | 含义 |
|---|---|
| 待确认 | 这张图还没点「确认」 |
| 已通过 | 已确认(`reviewed=true`) |
| 需重拍 | 被标记重拍 |

### 4. 检查器(右栏)

| 元素 | 含义 | 同源关系 |
|---|---|---|
| 已处理 X/Y | 本批次已确认张数/总张数 | X=全批 `reviewed` 任务数 |
| 待处理 N | Y−X | **与顶部「导入台账(待处理 N)」括号里是同一个数** |
| 类型徽章(如 百货·免团号) | 这张图按什么规则审 | 文件类型+店家档案派生 |
| 三色灯 ✓通过 / !核对 / ✗必改 | 绿=可跳过;黄=机器有疑点/外籍护照式/日期年份可疑,瞄一眼;红=必填为空或格式错 | 字段值+格式规则+机器疑点标记 |
| 团号徽章 ✓渠道模式:XXX | 团号命中团号表,XXX=表里登记的模式 | `groupNoMatchStatus=matched` + `modeRawPre` |
| ⚠团号未命中 | 表里没这个团号,改完保存自动重查 | `not_found` |
| ⚠表里登记的是别家店 | 团号在表里但店对不上 | `store_mismatch` |
| ⚠该团号对应多个渠道 | 一号多代理,必须人工点选 | `mode_ambiguous` |
| …团号表解析中 | 表还在后台解析,稍后自动匹配 | `pending_table` |
| 机场票·无团号 | 团号="无",照常审 | `no_group` |
| 橙色动作签(发小票17群/S活动红标签…) | 该模式有时效性人工动作 | 模式矩阵 actions(目前走出厂矩阵) |

### 5. 顶部

| 元素 | 含义 |
|---|---|
| 批次下拉 | 切批次 |
| **导入台账(待处理 N)** | N>0 时禁点;N 与检查器「待处理」同源,全部审完才亮 |
| 红条(顶部) | 最近一次动作被拦的**当前**原因(保存成功即清;点「定位到这张图」跳到出问题的那张) |
| 绿条 | 动作成功提示,4 秒自动消失 |

## 二、代理工作台(/agents)

### 1. 客户组八状态(每组恒处于其一)

`待重拍 → 识别中 → 待建档 → 待确认团号 → 待审核 → (待补救 | 待结算确认) → 已通过`

| 状态 | 意思 |
|---|---|
| 待重拍 rephoto | 有图等重拍 |
| 识别中 recognizing | OCR 在跑 |
| 待建档 ready_for_sync | 识别完等进批次 |
| 待确认团号 tour_pending | 等表态/团号确认 |
| 待审核 review_pending | 在审核台排队 |
| 待补救 needs_remedy | 结算时进了补救台 |
| 待结算确认 needs_confirm | 等在模式面板点确认 |
| 已通过 passed | 全链完成 |

### 2. 顶部六张统计卡(X/Y = 当前选中代理 / 全部代理)

| 卡 | 口径(2026-07-13 拍板) |
|---|---|
| 客户组总数 | 全部组数 |
| 待审核 | 待确认团号 + 待审核 两态之和 |
| 完成 | 已通过 |
| **未完全通过** | **待补救 + 待结算确认** |
| 今日新增 | 今天建档的组 |
| **异常待处理** | **待重拍 + 待补救** |

> ⭐**数字对不上的第一大原因在这里**:「待补救」**同时计入**「未完全通过」和「异常待处理」两张卡——
> 两卡相加会大于真实组数,这是拍板口径(两个视角看同一批问题),**不是 bug**。
> 第二大原因:代理工作台的数据是**投影库**(事件推送+每 15 分钟兜底核对),
> 与审核台的实时数可能**短暂差一拍**,等一会或刷新即平;差超过 15 分钟才值得报障。

## 三、同源对照表(哪些数字其实是同一个东西)

| 底层字段(存在任务上) | 驱动的所有显示 |
|---|---|
| `reviewed`(已确认) | 任务行「已通过」/ 组行「待审N·已审完」/ 检查器「已处理X/Y·待处理N」/ 导入台账括号 N |
| `rephotoRequested` | 任务行·组行·过滤chip「需重拍」/ 代理台「待重拍」/「异常待处理」的一半 |
| `tourStance`(表态) | 「待匹配N」/ 回执卡「小票已全部表态」/ SLIM 免审资格之一 |
| `groupNoMatchStatus` + `modeRawPre`(预匹配) | 团号徽章全家 / 模式 chip / 动作签 / 结算终匹配起点 |
| 组级 `settlementStatus`(结算落盘) | 审核台「已结算·待确认模式·待补救」/ 代理台「待结算确认·待补救·已通过」/「未完全通过」两半 |
| 代理台投影 `status`(八态) | 六张统计卡全部 |

一句话:**审核台读任务原始字段(实时),代理工作台读投影(准实时)**——同一件事两套读法,短暂不一致是架构特性。

## 四、日度补救(/daily/remedy)

| 元素 | 含义 |
|---|---|
| 行 | 结算时没走通的台账行(团号未命中/日期超窗/店对不上等) |
| 来源标记 | workbench=审核台结算产生(可点「定位审核台」跳回源组);导入=表格导入产生 |
| 组级补救 | 同团号+同代理整组一起改(纯日期类仍逐行) |
| 「确认模式」 | 人工定渠道模式,直接标 matched 不再查表 |
