# qwen3-vl-plus 高清压力测试报告(2026-07-21)

用户问:确定有 qwen3 权限吗?大批量并发会不会出问题?—— 用真实服务器图(stage4 的 846 张,
含护照/小票/百货)阶梯加并发裸打 qwen3-vl-plus@2400 的真实版面 prompt(不经 withRetry,直接看原始 429),
找并发天花板。**结论:权限确认有;大批量不会撞限流,并发 64 / TPM 100 万都零 429。**

## 一、权限:确认有 qwen3-vl-plus

本轮压测 + 前几轮实验累计对 qwen3-vl-plus 成功调用 **1500+ 次全部 200**。
之前的 403 是 `qwen-vl-max-latest` / `qwen2.5-vl-72b` / `qwen3-vl-max` 这几个**别的**模型无权限,
**qwen3-vl-plus 本身完全可用。**

## 三、结论:大批量不会出问题

1. **零限流:** 并发一路加到 64、有效 TPM 冲到 **100 万/分钟**,**全程 0 个 429**;持续 250 张连打也 0 个 429。
   qwen3-vl-plus 的限流额度远高于 qwen-vl-max(memory 记 max@1280 并发 12-16 就触 429)——是**更高的档位**。
2. **延迟稳定:** p50 一直 ~8s、p95 ~14s,加并发不劣化 = 服务端没排队,我们远在 qwen3 容量之内。
   (~8s 是单图高清延迟,靠并发拿吞吐。)
3. **吞吐充足:** 单客户端就能到 90-206 张/min。生产日量 ~1 万张,按并发 12(~59/min)算 **~2.8 小时**跑完、
   并发 24 约 **1.9 小时**,毫无压力。
4. **错误率:** 250 张里 1 个 HTTP 400(0.4%,单张坏请求/瞬时)——生产管道的 withRetry + qwen_failed 兜底会把它转人工,不是限流。

## 四、纠正:earlier 部署审计里"降并发到 3-4"是错的

之前审计说"高清把 TPM 从 ~12 降到 ~3-4,要降 PREPROCESS_MAX_CONCURRENT"——**那是拿 qwen-vl-max 的老限额外推,压测证伪。**
qwen3-vl-plus 并发 64 都不限流,**PREPROCESS_MAX_CONCURRENT 不用降,现值(生产 10)甚至可再往上调**去缩短大批量耗时。
(已在部署审计文档同步纠正。)

## 五、诚实边界(仍需在阿里云控制台确认的)

- 本压测是 **pass1(单次版面调用)** 负载,是限流的主体;全管道另有二遍/补救调用,但都是更小的裁片,叠加不改变"不限流"结论。
- 测的是**分钟级速率限制**(RPM/TPM),全程零 429。但**账号日总量/额度上限(daily quota / 余额)没测**——
  真跑几十万张的超大批前,去控制台看一眼日配额与余额,别把账户欠费/日限当成识别故障。
- 0.4% 的瞬时 HTTP 400 若在生产成片出现要查(图损坏/内容审核),但当前是正常噪声,管道已兜底。
