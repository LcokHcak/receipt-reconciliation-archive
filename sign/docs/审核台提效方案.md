# 审核台提效方案 —— 对标成熟审单系统(2026-07-21)

> **v2 修订(用户三问后定稿方向)**:
> 1. **弃"按模式手配 relax/slim"**,改为**「记哪些列」单一真相源自动驱动免审**:配置台勾掉的列,命中团号后自动从必审集移除(映射:小票号→receiptNoFinal、购买/出境日期→对应Final;店家=锚不免;团号=表态步本就要过;姓名/护照号在护照任务上审且交付夹名要用,不跟随)。3列模式命中后必填集自然为空=等效快车道,无需第二个开关。安全边界:仅命中后生效/配置缺失回落全审/锚字段永不免(机制均已有测试锁死)。
> 2. **免审的形式要可见化**:现状"免审"=确认不拦但字段照显(用户体感"没变化"的根因)。改为免审字段折叠成灰字一行「本模式不记:XX(自动带过,无需核对)」,需审字段照常,全绿出常驻横幅「本票只需核对团号——Enter 通过」;值保留可展开可改。
> 3. **直通道分级**:3列模式=有能力(团号命中表即自验;护栏=同组一致+模糊候选进人工+模式错误率降级),先"机器预通过+人工批量确认"灰度1-2周再放全自动;**全记模式=现在不上**(金标实锤纯OCR放行不可行、90.3%全对仍≈1成票带错、票号无校验位)——前置条件=月度对账P4/P5回填闭环+抽检面板,建好前不碰。
> 执行顺序:①columns自动免审+可见化 → ②决策树重排 → ③3列模式直通灰度。以下原文保留作背景。

> 背景:1 人/小时 ≈25 客户组(≈144 秒/组)。用户痛点:①"不用记"的模式审核区没变化,照样全审;
> ②流程乱——团号对/错是什么样、百货看什么不看什么、误分类双向怎么改、命中模式后该写什么,全靠操作员背规则。

## 一、症结诊断(为什么慢)

**1. 三层配置语义割裂——这是头号症结。** 系统里有三个独立开关,业务上是一件事,配置上互不连通:

| 开关 | 管什么 | 生产现状(2026-07-21 直读) |
|---|---|---|
| 记哪些列(columns) | 只管批次导出 Excel 的值 | 8 个模式部分记(如新罗V团-新琪只记 3 列) |
| 审核审哪些字段(relax) | 命中团号后放宽必审 | **29 个模式全部为空——没人配过** |
| 快车道(slim) | 命中后整票免审直接过 | **29 个模式全部关闭——没人开过** |

结果:「新罗V团-新琪」业务上只要 记录日期(自动)/代理(自动)/团号(表态步已验),**审核区却仍必填 8 字段**——纯粹浪费。"不用记的处理也花很长时间"的根因即此:**记哪些列 ≠ 审哪些字段,而后者从来没配过**。

**2. 流程状态机在操作员脑子里,不在屏幕上。** 团号命中/未命中/无团号三态、百货三家看什么、误分类怎么改——机制全都存在(本轮 98 个边界用例验证过),但散落在表态块/一等档按钮/字段区/结算面板四处,新人要背。

## 二、成熟审单系统的三个通用机制(对标)

参考发票/单证自动化行业(ABBYY FlexiCapture、Kofax、Rossum、Hyperscience)与内容审核队列的共性设计:

1. **分道处理(Lane Triage)**:进件自动分三道——直通道 STP(零人工)、快道(一眼确认)、例外道(人只处理例外)。行业标杆 STP 率 60-85%,人工只碰例外。**我们现状=全量走例外道。**
2. **例外优先(Review by Exception)**:界面只呈现低置信/校验失败/必审字段,其余折叠成绿色摘要,一键全收。人眼扫描面积决定速度。
3. **键盘流+决策树 UI**:一屏一决策,Enter 贯穿主路径;把"该看什么"直接画在屏幕上而不是写在培训文档里。

## 三、快赢:纯配置,零代码,当天生效(预计 25→40 组/小时)

系统机制已齐(relax/slim 本轮实测+30 用例锁死),**只差把「记哪些列」的业务意图同步到「审哪些字段」**:

### 3.1 八个部分记模式的 relax 配置映射表(照抄即可)

| 模式 | 开 slim 快车道 | relax(去勾) |
|---|---|---|
| 新罗V团-新琪 / 济州新罗SG-道辉 / 济州乐天SG-道辉 / 新世界SG-振华 / 新世界SG-荣晨国际(只记3列) | **✅ 开**(命中=免审直过) | — (slim 已覆盖) |
| 新罗SG-新琪 / 济州新罗SG-宋总(记5列,缺 小票号/姓名/护照号) | 可选 | 小票号(receiptNoFinal) |
| 现代-JEOCU(记4列,缺 购买/出境日期/姓名/护照号) | 否(票号要审) | 购买日期/出境日期 |

> 说明:①姓名/护照号在护照任务上审,不在小票必审集内,无需 relax;②slim 三闸(小票+表态匹配+团号表命中)缺一自动回落全审,SLIM 谓词已有哨兵用例守护;③relax 只在命中团号后生效(时序墙已测),未命中票仍全审——安全。

**效果测算**:只记 3 列的五个模式,组耗时从 ~144s → **~15s**(表态一下 Enter、确认 Enter、护照全绿 Enter、确认即结算收口)。按这些模式占单量 30-40% 估,整体 25→38-45 组/小时。

### 3.2 配置台小改(P0.5,半天代码)

「记哪些列」保存时,**自动提示**"检测到本模式不记 X/Y 字段,是否同步放宽审核?"一键把 columns 映射进 relax(映射规则:不记 receiptNo→relax receiptNoFinal,不记 purchaseDate/departureDate→relax 对应日期;name/passportNo 属护照任务不映射)。从根上消灭"两处配置漂移"这类认知落差。

## 四、P1:审核台决策树化(UI 重构,预计再 +30%)

把已存在的机制重排成**一条从上到下的决策流**,操作员不再背规则:

```
┌ 第一步 · 团号(现表态块,提级为全宽步骤条)─────────────────┐
│ [OCR预填团号] → Enter                                        │
│  ✅命中 → 大绿横幅「新罗V团-新琪 · 本模式只审团号,其余免审」  │
│           (slim 模式直接显示:再按 Enter 完成本票)            │
│  ⚠️未命中 → 黄横幅+两个按钮:「核对后仍匹配(换表自动复核)」  │
│            「选模式补救」(现结算面板内联补救前移到这里)       │
│  ⬜无团号 → 灰按钮「无团号·直接确认」(机场票,已有)          │
│  🏬这其实是百货 → 乐天/新世界/现代 三钮(已有,保留在此)      │
└──────────────────────────────────────────────────────────┘
┌ 第二步 · 字段(例外优先渲染)─────────────────────────────┐
│ 只渲染本模式必审字段;不审的折叠为一行灰字:                   │
│ 「本模式不记:小票号/姓名/护照号/日期(自动带过,无需审核)」   │
│ 百货按店渲染:乐天=身份2+交易号+金额+门店+品牌;               │
│ 新世界/现代=交易号+金额+上家(免身份,面板顶部一行说明)       │
│ 全绿 → 顶部常驻「✓ 一键确认(Enter)」                        │
└──────────────────────────────────────────────────────────┘
┌ 类型改判 · 常驻顶栏(护照|小票|百货 三钮,已有 tier1 提级)──┐
│ 百货误判成小票:点[百货]→选店(乐天/新世界/现代)             │
│ 小票误判成百货:点[小票]→选免税店家                          │
│ 双向都是两击,按钮旁加一行"改判会清空已填字段"提示(机制已有) │
└──────────────────────────────────────────────────────────┘
```

关键点:**不新造机制,全部是现有能力的重新编排**(表态块/prematch徽章/内联补救/tier1按钮/百货面板/全绿横幅/确认即结算都已存在且被测试锁死),改动集中在 ReviewView 布局层,风险低。

## 五、P2:直通道+抽检(吞吐质变,预计 60-80 组/小时)

行业终局形态:**命中即自动通过,人工只抽检**。
- slim 模式 + 团号命中 + 护照全绿的组 → 系统自动确认+结算,不进人工队列;
- 人工按比例抽检(如 10%)+ 金标对账周报兜底(基建已有:每张已审票=零成本金标);
- 出问题的模式自动降级回人工道(按模式统计错误率)。
- 前提拍板:业务接受"机器直过+事后抽检"替代"张张过目"。发票自动化行业在此形态下 STP 60-85%。
