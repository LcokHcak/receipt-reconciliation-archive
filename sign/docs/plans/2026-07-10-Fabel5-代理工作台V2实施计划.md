# Fabel5 代理工作台 V2 实施计划

> **For Fabel5:** 按任务顺序实施，每个任务先写失败测试，再做最小实现并单独提交。不要跳过回填校验、权限测试或真实 UI 测试。

**Goal:** 在不复制审核和月度业务逻辑的前提下，将现有单批次“代理视图”升级为客户级、跨批次、服务端分页的独立代理工作台。

**Architecture:** 以 `customer.json` 为客户/代理锚点，以 batch/group/task 为审核覆盖层；在 `workbench.sqlite` 建可重建 `agent_workspace_customer` 读模型和不可丢失的 `workflow_task` 任务表。前端用独立 `/agents` 三栏页面消费服务端分页 API。

**Baseline:** `1b63bd5`。旧的 `agent_workspace_group` 和 `/agents/:workspaceKey` 计划作废。

**Tech Stack:** Node.js、Express、`node:sqlite`、Vue 3、Pinia、Node Test Runner/Vitest、Playwright。

## 实施红线

1. 不改 `scripts/probe_qwen_qps.js`；它是当前工作区已有的用户改动。
2. 不在请求路径扫描整个 customer/batch 文件树。
3. 不让空 task agent 覆盖 `customer.json.agentName`。
4. 不解析 `workspaceKey` 作为自然月。
5. 不把 workflow task 当可重建缓存；完成历史必须备份。
6. 不复制团号确认、OCR 审核、月度补救、交付生成的写逻辑。
7. 未经用户明确指令不部署；先提交代码、测试结果和迁移 dry-run 报告。
