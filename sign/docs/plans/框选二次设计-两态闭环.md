# 框选二次设计:两态 + 闭环

> 状态:**设计稿,未改代码**。等拍板。
> 日期:2026-07-30
> 起因:用户反馈三条 ——
> ①「护照任务默认就该是原图+红框+放大到该任务中心,不该点了原图才看到框」
> ②「4 张小票识别成 3 张,我工具太多了,点哪个?怎么加?什么流程?」
> ③「点到原图才开始画框,画什么框?怎么画?我画了有什么反应?**整套流程没有闭环**」

---

## 〇、先承认诊断

**第三条是对的,而且根因不是"少做了一步",是我把一个视图当成两件事用。**

审核台的中栏现在同时被要求干两件互相冲突的事:

| 要干的事 | 需要什么 |
|---|---|
| **核这张票的字段** | 那一块要**大、清楚**,别的东西越少越好 |
| **发现漏识别了一张** | 要看**整张照片的全貌**,才知道哪块没被框住 |

一个视图满足不了,于是就往上堆开关:`字段框 / 当前字段 / 查看原图 / 框选 / 显示全部 / 画框 / 清除框`。
**实测最多 18 个控件在一条工具栏上。** 工具多的根因是视图没分开,不是按钮设计得不好。

---

## 一、两条实测约束(它们决定方案形状)

### 约束 A:整张原图**又大又不清楚**

| | 中位 | p90 | 最大 |
|---|---|---|---|
| 切片(走 `/storage-preview`) | 115KB | 221KB | 592KB |
| 客户库 `_original`(「查看原图」拉的) | 299KB | **4.9MB** | **14MB** |

而且分辨率更要命:

- 切片 = 从原图**全分辨率**裁出 → 缩到 `COMPRESS_MAX_SIDE = 2400` 长边 → **那张票 ~2400px**
- 整张原图预览 = 缩到 `PREVIEW_MAX_EDGE = 1600` → 4 票合影里**一张票只剩 ~400px**

**所以"默认显示整张原图"不可行**:慢(p90 4.9MB;0727 反馈#11「图片缓冲不出来」就是这个),
而且那张票只有切片的 1/6 分辨率,**票号和日期会读不清**。

### 约束 B:框是原图坐标系的

任何"在切片上画框/换算框"的做法都要处理坐标系。而如果**预览本身就是按框裁的**,
坐标系问题自动消失(和现在的切片同一个系)。

---

## 二、方案:两态,各司其职

### 主态「核字段」—— 默认,零点击

**看到什么:按当前任务的框裁出来的预览**,带一点外扩(能看到隔壁一角,知道自己在哪)。

- 这**天然就是**用户要的「放大放到这个任务中心」—— 裁出来的图本身就是那张票占满画面
- 红框画在预览里,标出"框的边界在哪" → 外扩带进来的隔壁一角一眼可辨
- 快(1600px ≈ 200-400KB)且清楚(那张票占满 1600px,比现在的切片视图不差)
- **磁盘上不产生切片文件** —— 这正是「直到导出才按框切」

**怎么实现**:`/storage-preview` 加一个 `?box=x1,y1,x2,y2` 参数 —— 先按框裁再缩放。
缓存键加上 box。裁剪几何**复用 `lib/delivery_render.computeCropRect`**,
于是**审核看到的构图 = 交付出的构图**,不会出现"审的时候好好的、导出后不一样"。

### 副态「看全图」—— 一键进,只干一件事

**看到什么:整张原图 + 所有框**。这个态存在的唯一理由是**发现漏识别**。

- 所有已识别的框:淡灰
- 当前任务的框:红
- **没被任何框覆盖的区域:压暗**(而不是给框加高亮)—— 于是"漏掉的那张票"是画面里唯一亮着的东西
- 这一态里只放**一个**主动作:**「这里还有一张票」**

这一态可以放心用 1600px 预览:它的任务是"看全貌找漏的",不是"读字段"。

## 三、「4 张识别成 3 张」的闭环(逐步)

用户问的是「点哪个?怎么加?画什么框?画了有什么反应?」。逐步答:

```
1. 审核员在主态核字段,顺手瞥见右下角提示:「这张照片上识别出 3 张单据」
   ↓ 点「看全图」
2. 整张原图 + 3 个灰框,**没被框住的那块亮着**(其余压暗)
   → 一眼看到"右下角那张没被框"
   ↓ 点【这里还有一张票】(整个视图里唯一的主动作,红橙)
3. 光标变十字,顶部一句话:「把那张票整个框进去,松手即保存」
   ↓ 拖一个框,松手
4. 系统一次做完四件事,并逐条回报:
   ① 新建一条小票任务,**带上你画的框**
   ② 用这个框裁出区域**单独调一次 qwen 重读字段**
      (复用 `retrySuspectReceipt` 已有的"裁子区域→重喂→坐标映射回全图")
   ③ 自动跳到那条新任务(回到主态,按新框裁的预览)
   ④ 顶部提示:「已新增 1 张小票,字段是从这一块重读出来的,请核对」
5. 审核员核对字段 → 确认 → 继续
```

**现在的路径对比**(为什么不闭环):

```
「更多」→「同图补小票」→ 得到一条**空白**任务(没框、字段全空)
  → 自己照着图填 4 个字段
  → 而且这条任务**会被交付护栏拦**(共用图片文件且没框)
  → 导出时才在「导出说明.txt」里看到它没进包
```

三处断裂:**没框**、**字段要手填**、**要等导出才知道有问题**。第 4 步的四件事正是把这三处接上。

### 另外两个动作(次级,收进「更多框选」)

- **重新框这一张**:模型框歪了 → 重画当前任务的框(已有 `POST /doc-box`)
- **清除我画的框**:撤销(已有)
- **这两张是同一张票**:票号重复时合并/删一条(现在只有提示,没有动作 —— 见第六节)

## 四、工具收敛:18 → 9

| 现在(一条工具栏 18 个) | 改后 |
|---|---|
| 适应 / − / 50 / 100 / 200 / 400 / + / 滑块 / ↺ / ↻ | **保持**(看图基本功,10 个) |
| 字段框 / 当前字段 | **保持**(2 个,主态里) |
| 查看原图 / 看裁切图 | → 合成一个**「看全图」**(1 个) |
| 框选 / 显示全部 | **删掉** —— 主态恒显示当前框;全图态恒显示所有框。开关本身是多余的 |
| 画框 / 清除框 | → 副态里的**「这里还有一张票」**(1 个),改框/清除收进次级菜单 |
| 缩略图定位器 | **删掉** —— 主态就是"放大到这个任务",副态就是全图,不再需要第三个"我在哪"的东西 |

**净变化**:主态 12 个(基本功 10 + 字段框 2 + 看全图),副态 2 个(回主态 + 这里还有一张票)。
**任何一屏都不超过 13 个,而且每个态里的按钮都是那个态用得上的。**

1. **字段框坐标系**:0730 我把 qwen 字段框换算到了**切片**坐标系(`toCropRelative`)。
   主态预览是按框裁的 → **坐标系不变,不用改**。✅ 但如果哪天主态改成整张原图,这里必须同步改。

2. **缩略图定位器删掉**后,`showLocator` / `locatorOrdinal` / 折叠状态那套都要清干净,
   别留死代码。

3. **一图一票的 72% 任务**:它们没有兄弟框,主态 = 整图(裁剪框就是整图)。
   行为和今天等价,只是走了同一条代码路径。**这部分要单独回归一次**,
   因为今天它们走的是"切片 + 350% 默认放大"。

## 六、还没闭环的一处(要拍板)

「**这两张是同一张票**」现在只有提示、没有动作:

- 生产实测 130 对(0.506%)框重叠且票号相同 = 同一张票出了两条记录
- 界面会说「和另一条任务票号相同…请核对后删掉多余的那条」
- **但"删哪条"要人自己判断,而且删任务的入口在「更多」里**

要不要给一个「**这两条是同一张 → 合并**」的直接动作?
它涉及删任务(有结算守卫),所以我没自己拍。

## 七、分期

| 期 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| **1** | `/storage-preview` 支持 `?box=` (裁剪几何复用 delivery_render) | 中 | 低,纯新增参数 |
| **2** | 主态改成"按框裁的预览"+ 红框标边界;删掉框选/显示全部/定位器 | 中 | **中** —— 改的是所有多单据任务的默认视图,72% 单票任务要回归 |
| **3** | 副态「看全图」:压暗未框区域 + 唯一主动作 | 中 | 低 |
| **4** | 「这里还有一张票」闭环:建任务+带框+重读字段+跳转+回报 | **中偏大** | 中(碰写锁 + qwen 调用) |
| 5 | 「合并同一张票」(等第六节拍板) | 中 | 中(碰删除守卫) |

**建议顺序:1 → 3 → 4 → 2**。

把第 2 期(改默认视图)放最后,理由:第 3+4 期已经把用户最痛的「发现漏票没闭环」解决了,
而第 2 期动的是**每天每条任务**的视图,风险最大。先让闭环跑顺,再动默认。
