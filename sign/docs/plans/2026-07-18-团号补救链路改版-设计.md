## P1 审核台「当下处理」(核心)

**后端(极小)**:
- readSettledReceipts 映射补 `id: row.id`(一行);
- 共享失败原因人话:补救台 REASON_HINT 搬到共享 lib(或 statusLabels 扩展),禁第二副本。

**结算面板增强(ReviewView settleResult 面板)**:
1. 未命中行(!isReceiptModeFound)在 settle-row 内展开补救区:
   - 失败原因人话(TOUR_MATCH_STATUS 字典+REASON_HINT):团号未命中/日期超团期/代理不一致/团号多候选…
   - **模式类原因**(tour_not_found/agent_mismatch/tour_ambiguous/store_mismatch):模式下拉
     (候选=fetchBatchGroupCodes(batchId,tourNo) 命中优先 + fetchModeMapping(r.workspaceKey) 全量池)+「或手填」+「确认补救」
     → PATCH /workspaces/${r.workspaceKey}/ledger/${r.id}/fields {modeRaw, manualRemedyConfirm:true}(与补救台完全同构,零第二套口径)
   - **日期类原因**(date_out_of_window/date_missing):日期输入+「改日期重试」(PATCH purchaseDate;
     窗口内自动重跑翻 matched,跨月自动迁移由后端既有逻辑处理);不提供选模式硬 confirm
2. 组级「同模式应用到未命中」:仅当组内未命中行**同团号+同店**且非日期类时出现;多团号/多店时禁用并警示(F9)
3. 每行补救成功即时更新行 chip;**全部未命中清零后自动调 confirmCurrentGroupModes**(F7)
   → settlementStatus 翻 settled,stampLocalGroupSettlement 即时刷组徽章
4. 「稍后处理」按钮 = closeSettle(纯关面板,F8);面板脚注提示:"稍后处理的行在异常补救页;重新结算会重新查表核对"(F6)
5. 随批修 F13(r.mode→r.modeRaw)

**测试**:后端 id 契约;前端面板契约(补救区/日期分流/组级收窄条件/confirm 串接);补救台同构性(PATCH payload 同款)。

## P2 互相找回 + 客户信息

1. **审核台→补救台精准落位**:组卡片「待补救」徽章加点击(GroupedTaskList emit)→
   `/daily/remedy/${ws}?batch=${ws}::${batchId}&customer=${groupKey}`;
   结算面板「去补救」同款带参。补救台 onMounted 读 query:batch→selectedBatchKey,
   tour→展开对应组卡片(组 key `${ws}::${tourNo}::${agent}` 前缀匹配),customer→filteredRows 加过滤(~30 行,零后端)。
2. **补救台→审核台**:行级深链已在产;补组卡片级「定位审核台」(单批次组直接跳,跨批次按行)。
3. **客户信息弹窗**(补救台组内行+平铺行):按行 sourceBatchId fetchBatch → 同 sourceGroupKey 的全部 tasks
   =该客户护照+全部票(姓名/护照/票号/店/状态)+原图(复用 Drawer 的 ImageViewer 手法)+「定位审核台」。
4. **平铺改客户单元**(07-17 方案②):平铺视图从逐票行改为按 sourceCustomerId 聚合的客户卡(姓名/护照/N 张票/原因),
   卡内逐票补救;命名改「按客户」。

## P3 韧性硬修(排查抓出的既有缺陷,非新功能)

1. **F6 补救结论抗重结算**:cleanOldUnmatchedRows 跳过 manual_locked_fields 含 tour_match_status 的行
   (与 A1 抗 bill_match 重跑同族;新插行被业务键预查去重跳过,无孤儿/双行风险——排查已核)。回归测试。
2. **F11 混合组一键同模式**:补救台 submitGroup/一键全部 排除 date_* 行(逐行过滤+提示跳过数)。
3. **F12 永久 pending GAP**:无 confirm 的手改不把 tour_match_status 盖进 manual_locked_fields
   (状态列只在 manualRemedyConfirm 时上锁),或 resetTourMatchForRematch 先解 date_out_of_window 状态锁。取前者(源头收口)。

## 红线

1. 补救 API 单一口径:面板/补救台都走 PATCH manualRemedyConfirm,禁第二套;
2. 失败原因文案单源(REASON_HINT 搬共享,补救台改引用);
3. 票级 modeManualPick 不动(它只管审核侧车道,结算权威自查表——分叉场景由 F6 修复消除主害);
4. 每期全量测试看 fail 数+build+门禁+code-reviewer;部署等口令。
