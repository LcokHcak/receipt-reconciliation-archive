## 二、审核字段接配置:三个配置体,三种生效时机

```
生效必填集 = ①审核基线(docType) ⊕ ②店家档案(百货,按店) ⊕ ③模式微调(仅 matched 后)
                 全局、审核即生效        店已知、审核即生效        预匹配命中才叠加
```

1. **审核基线**(新 kind='review_base',三份:passport/receipt/flight)
   - seed 自现 DOC_TYPE_FIELD_RULES(护照:姓名+护照号;小票:店/票号/团号/购买/出境;机票=other 提示件)。
   - 消费方=getRequiredFieldRules 唯一咽喉(P0 手法:resolver 命中用配置,没配/坏配回落出厂)。
   - ⚠️高危区:改基线影响**所有在审票**。护栏=保存前影响面预检(“当前活跃批次将有 N 张票新增必改”)+二次确认+audit。
2. **店家档案**(kind='store',已入库)——本期接上消费方:
   - buildDeptReceiptFieldRuleSet 改读配置档案(回落内置 PROFILES);前端百货面板同源派生。
   - 档案里 passportFree/组级口径字段**只读展示**(冻结区,见边界1)。
3. **模式微调**(挂在现有 mode 配置 payload 里,新增 `review` 段):
   - `review: { relax: ['departureDateFinal'], require: [], slim: false, sActivityMark: null }`
   - 只在 groupNoMatchStatus=matched 时叠加(SLIM 车道同款三条件);not_found/待归类=纯基线。
   - **SLIM 收编**:`slim:true` 取代 WORKBENCH_SLIM_MODES ENV(ENV 保留为紧急覆盖,优先级:ENV>配置)。

## 三、UI 重组(按模板形态)

### 1. 左侧四区导航
- **配置台总览**:顶部已配置模式卡(现有)→ 点卡进入配置区
- **字段管理**:字段注册表只读表(中文名/来源/可导出/适用类型)+「新字段申请」登记入口(真新字段仍走代码,P1 已定边界)
- **配置日志**:全 kind 版本流水聚合(操作人/时间/对象/备注/回滚按钮)= 模板⑥修改日志的全局版
- **帮助文档**:链到 业务规则总览 / 效果图 / 字段字典 三份 SOP

### 2. 配置区(选中一个模式后,模板②的结构)
- 1) 模式名称(现有,正名归一)
- 2) 审核需求字段勾选:
  - A类 radio 由系统判定并展示(百货模式→只显 C类区;非百货→只显 B类区)——**不许手动切**(百货与否由店家常量决定,手切=造不一致)
  - C类=该百货店档案字段勾选(直接编辑档案;三家百货各自的模式卡进来看到各自档案)
  - B类=基线的**只读底色** + 模式微调勾选(去勾=relax 微调;基线本身另在「审核基线」抽屉里改,带影响面预检)
- 3) 该模式下的【导出】需求勾选(模板③):
  - 列表=「Excel·台账列(内置)」+ 命中本模式的文件夹计划;序号/启用勾选/修改/停用
  - 新增导出配置 → 预填 scope=当前模式的 P2 计划编辑器
  - A类文件夹页签=P2 编辑器 + **分类方式三选皮肤**(见下);B类 Excel 页签=columns 勾选(现 P1 面板迁入)
- 4) 冲突检查(见下)
- 5) 保存本模式 + 顶部「保存所有配置」

### 3. 分类方式三选皮肤(模板的 ①单一字段/②多字段并行/③命名方式)
每级分类 radio 三选,本质都生成 level.template:
- 单一字段:选一个字段 → `{field}`
- 多字段并行:多选字段 → 按选择顺序拼接 `{f1}{f2}`(=模板里的"并行"语义:组合键分夹)
- 命名方式:自由模板输入(现 P2 输入框,高级用)
> ⚠️边界确认(待拍板):"多字段并行"如果你的本意是**并列生成多棵文件夹树**(同一批文件按字段A分一套、按字段B再分一套),那等价于**多条导出计划**——界面上用"再建一条计划"表达,不塞进一级里。按截图勾选形态,我按"组合键拼接"理解。

### 4. Excel 列扩展(百货明细表导出)
模板 B类勾了 品牌/交易编号/交易金额/门店编号/模式 等——超出台账 8 列。
落法:columns 从固定 8 键扩展为 **8 基础列 + 百货扩展列**(brand/receiptAmount/branch/upstream/mode,
仅百货模式可勾;导出层按勾选出列)。schema 校验白名单同步;非百货模式勾百货列=硬冲突。

### 5. 冲突检查 v2(模板④,升级为硬)
- 输入:该模式全部**启用**的导出(Excel 列+文件夹计划 tokens)
- 判据:每个所需字段 ∈ 有效审核集(基线⊕档案⊕微调) ∪ 系统派生集(收票日期/代理/模式/customerId/docLabel/i)
- 输出:模板同款表(冲突类型/字段名/问题说明/处理建议);**硬冲突=该导出禁启用**(可存草稿),软警告可启用
- 例:百货模式导出勾「团号」→ 硬冲突"百货无团号"(现软警告升级);非百货计划用 {receiptAmount} → 硬冲突"该字段仅百货有来源"

## 四、边界问题处理(逐条,含裁决建议)

1. **护照顶层开关不进配置**:B类"护照(勾选)"若理解为"该模式可以没护照"→ 撞组级安全闸(passportFree 按店管理,冻结区)。裁决:护照子项(姓名/护照号)可配(基线层);**顶层开关只读**,免护照口径仍由店档案 passportFree 承载。
2. **时序墙重申**:模式微调仅 matched 后生效;UI 在微调区显著标注"团号命中后生效;未命中按基线全查"。
3. **基线修改爆炸半径**:实时生效+影响面预检+二次确认+一键回滚;**新增必填**比放宽危险一个量级,确认文案区分。
4. **A类不许手动切**:百货与否=店常量事实,配置台只展示判定结果。手切开关会制造"配置说是百货、系统按小票审"的分裂。
5. **S活动开关**:默认名字推导;显式配置可覆盖;关掉只隐藏标记入口,已打标票的 sActivityFlag 不动。
6. **机票(勾选)**:机票=other 参考件,不入台账不设必填;该勾选映射为"审核台是否提示收机票件"(纯 UI 提示层),默认开。不造 other 必填闸。
7. **前端运行时化**:审核台字段面板改为启动拉 `/api/review-config`(有效集+版本水位),60s 缓存;拉失败→内置兜底(绝不锁死审核);配置变更→ops 水位推横幅"配置已更新,刷新生效"。
8. **每模式导出列表的启用语义**:文件夹计划=active 即启用(P2 现状);Excel 内置条恒在不可停用(台账必出),只可改列。
9. **一键保存**:顺序提交各脏区(基线/档案/模式/各计划),独立实体(店与店、店与模式)失败不中断、逐条尝试;有任何失败整体走红条汇总,逐条结果清单+失败项高亮;**不做跨条事务**(部分成功各条自身仍原子且可回滚,复杂度不值)。
10. **多字段并行语义**(见三.3,待拍板)。
11. **零变化承诺**:P3 上线时 review_base seed=现内置、微调全空、档案消费方切换有快照测试(seed≡PROFILES 已有)——不跑 seed/坏配置=行为与今天逐字节一致(P0 同款验收)。
12. **百货扩展列**:仅百货模式可勾;台账导出层新列只在勾选时出现,老 8 列文件格式不动(新列追加在右侧,上家表头文案可配)。
13. **配置日志页数据量**:版本流水按 kind+时间分页(每页50),不做全量拉取。
14. **权限**:全配置台 admin;基线修改可考虑再加"输入模式名确认"式二次门(待拍板,可先不加)。
