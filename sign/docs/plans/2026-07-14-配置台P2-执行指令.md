## 目标

把「交付包怎么分文件夹、怎么命名」从代码(mode_delivery 四规则/乐天百货包)变成 export_plan 配置;
新增交付需求从此零代码。P2 先做**引擎+预览+并存入口**,老规则 seed 成出厂计划;切换默认走 P4。

## T1 计划 schema(kind='export_plan',复用 config_entries)

```jsonc
{
  "planLabel": "济州道辉交付包",
  "scope": { "modes": ["济州新罗SG-道辉"] },        // 命中哪些模式(canonical 名);空=全部
  "levels": [                                        // 一级/二级/三级分类,每级=模板
    { "template": "{groupNo}" },
    { "template": "{groupNo}—{name}{passportNo:0,4}" }
  ],
  "naming": { "template": "{receiptNo}" },           // 叶子文件命名(不含扩展名)
  "emptyPolicy": "block_prefix",                     // block_prefix(默认拍板)|skip_log|placeholder
  "duplicate": "suffix",                             // 重名 _2/_3(既有先例)
  "includes": ["receipt", "passport"]                // 拷哪些件
}
```
模板 token=字段注册表 exportable 字段 + `{passportNo:0,4}` 切片语法;未知 token=schema 校验 400 拒存。

## T2 引擎 lib/export_plan_engine.js(纯函数,不碰磁盘)

`resolvePlan(plan, tasksByGroup) → { entries: [{srcPath, destPath}], blocked: [{reason, task}], skipped: [] }`
- 只算路径不落盘;sanitizeFolderLabel 复用;路径长度>240 进 blocked(Windows 260 预警);
- emptyPolicy=block_prefix:空值项进 blocked 并给 `缺{字段}_` 前缀建议(对齐 S活动缺票号先例)。

## T3 出厂 seed 扩展

seed_factory_config 增 export_plan 四条:济州道辉/现代三池/其他模式顶层夹/S活动双份 + 乐天百货门店双图。
⭐对照测试(核心验收):同一 fixture 批次,引擎 resolvePlan 产出的 destPath 集合 ≡ 现有
mode_delivery_export_service 实际产出(逐路径 deepEqual)——四规则各一条用例,乐天百货一条。
对不齐=引擎错,以老代码为准。

## T4 dry-run 预览端点

`POST /api/admin/config/export-plans/:name/preview {batchId}`(admin):
跑引擎不落盘,返回 `{tree, blocked, stats}`;树折叠 JSON(前端渲染文件夹树)。
批次不存在 404;>2000 entries 截断带 truncated 标记。

## T5 UI(ConfigConsoleView 加「导出计划」页签)

计划卡列表(出厂/自定义vN)+ 编辑区(scope 多选模式/levels 模板行+token 下拉插入/空值策略单选)
+ **预览面板**:选最近批次→点预览→文件夹树+blocked 红名单;保存/回滚/回落复用 P1 全套。

## T6 并存入口(灰度)

默认无人用=零风险;P4 才谈切默认。

## T7 收尾
