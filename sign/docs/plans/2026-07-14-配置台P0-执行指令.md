## T2 配置仓库 `repositories/mode_config_repository.js`

```sql
CREATE TABLE IF NOT EXISTS config_entries (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT NOT NULL,            -- 'mode' | 'store' | 'export_plan'(P2 才用)
  name TEXT NOT NULL,            -- 模式基名(normalizeModeName 后)/店家 family
  version INTEGER NOT NULL,      -- 同 kind+name 递增
  payload TEXT NOT NULL,         -- JSON
  active INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  created_by TEXT NOT NULL DEFAULT '',
  note TEXT NOT NULL DEFAULT ''
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_config_kind_name_ver ON config_entries(kind, name, version);
CREATE UNIQUE INDEX IF NOT EXISTS idx_config_active ON config_entries(kind, name) WHERE active = 1;
```

- API:`getActive(kind,name)` `getAllActive(kind)` `listVersions(kind,name)`
  `saveNewVersion({kind,name,payload,createdBy,note,expectBaseVersion})`(乐观锁:
  当前最大 version ≠ expectBaseVersion → 抛 CONFIG_STALE)
  `activateVersion(kind,name,version)`(事务内:全清 active→置1)
  `deactivate(kind,name)`(active 全 0=回落出厂)
  `maxVersionStamp()`(SELECT MAX(id) — resolver 缓存失效水位,一条 SQL)。
- 装配:workbench_server 现有 monthlyDb 注入;跟 audit_log_repository 同款风格。
- 单测:版本流水/乐观锁/active 唯一(部分索引生效)/deactivate 回落。

## T4 resolver `services/mode_config_resolver.js`

```js
createModeConfigResolver({ modeConfigRepository, logger }) → {
  getModeRecordRule(modeRaw),   // 形状与 lookupModeRecordRule 完全一致
  invalidate(),                 // 测试用
}
```

- 流程:normalizeModeName(basename)→缓存查(Map)→miss 则 repo.getActive('mode', base)
  →validateModeConfig(payload)(手写校验:columns 8 键 bool/receiptNoForm 枚举/actions 数组…)
  →合成规则(尾巴动作 SUFFIX_ACTIONS 与「不用记」仍按**原串**现算,与出厂同逻辑——
  从 mode_record_matrix 导出 `composeRule(hit, raw)` 复用,别抄第二份)
  →坏 payload/未命中 → `lookupModeRecordRule(modeRaw)` 出厂回落 + logger.warn('config_fallback',{name,reason})。
- 缓存失效:每次调用比对 repo.maxVersionStamp()(SQLite 单条 PK max,便宜),变了清 Map。
- ⚠️ mode_record_matrix.js 需小改:导出 normalizeModeName(已导)+ 把"尾巴合成"抽成可复用函数,
  出厂 lookupModeRecordRule 行为不变(现测试锁着)。
