# 代理工作台 Implementation Plan

> **已由 V2 替代：** 不执行本文的 `agent_workspace_group` 和

> [Fabel5 代理工作台 V2 实施计划](./2026-07-10-Fabel5-代理工作台V2实施计划.md)。

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将审核台内的单批次代理筛选页签升级为独立、跨批次、服务端分页的代理回溯与任务工作台。

**Architecture:** 保留 `batch.json/customer.json/sendback_queue.json` 为真相源，在现有 workbench SQLite 中增加可重建的 `agent_workspace_group` 查询投影。前端独立三栏页面分别请求代理、统计、客户组和任务 API，不再加载所有批次任务后在浏览器聚合。

**Tech Stack:** Node.js、Express、`node:sqlite`、Vue 3、Pinia、Vitest/Node Test Runner、Playwright。

---

## 实施前提

- 先由用户确认 [架构设计](./2026-07-10-代理工作台架构设计.md)。
- 实现时使用独立 worktree，避免覆盖当前工作区中 `scripts/probe_qwen_qps.js` 的未提交改动。
- 每个任务单独提交；不要在同一提交中重构月度交付、审核台字段编辑或代理主数据。

## 最终验收清单

- [ ] 所选月份跨可见批次聚合，reviewer 不越权。
- [ ] 代理、统计、客户组和任务均由服务端查询。
- [ ] 客户组列表使用游标分页，首屏不加载整批任务。
- [ ] 审核状态和模式样式符合飞书最终 Prompt。
- [ ] 去审核台准确定位客户组，返回后保留代理与筛选。
- [ ] 回发任务完成状态、操作人、时间刷新后不丢。
- [ ] 资料库接收并应用代理/模式筛选。
- [ ] 10,000 组 API P95 小于 300ms。
- [ ] shared memory、SOP、OpenAPI 同步。
