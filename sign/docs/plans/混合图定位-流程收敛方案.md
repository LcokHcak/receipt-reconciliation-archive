# 混合图定位 · 流程收敛方案

> 2026-07-30 · 起因:用户实测四问 +「这套流程太乱了,我审核员怎么操作」
> 目标(用户原话):**cover 住因为 ocr 识别导致的混合图识别定位问题**

---

## 〇、先把四个问题答清楚

### ① 「我画了框,然后呢?还是显示这个」

两个缺陷叠在一起,都是真的:

- **(a) 按钮在做不到的时候还亮着。** 你那条任务指向的是切片文件,后端
  `canAcceptManualBox` 直接拒(框的坐标系是整张原图,画到切片上对不上),
  但按钮一直可点 → 你点了、失败了、提示一个字没变。
  **已修,已上生产 `2d4fbad`**:做不到就置灰,文字直接写「画框(这条不行)」,悬停给理由。

- **(b) 就算框存下来了,也确实"什么都没发生"。** 现在画完框只多一条框线:
  字段不重读、你看的那张图不变。**画框没有闭环** —— 这是 P2 要解的。

### ② 「我不都是识别框了么,为什么还要按店重切」

因为「按店重切」是**框出现之前**的东西。它解决的是"切片文件本身切错了",
手段是让 qwen 重切一次。可只要审核台不再拿切片当主视图,就没有"切片切错"这回事了 ——
**框错就改框,不需要重切**。

「按店重切」唯一还站得住的用途是:*店档案判错了,想让 qwen 按正确的店重读一次字段*。
所以它应该改名降级、从"框有问题"这条路上彻底移走(P3)。

### ③ 「原图像素清晰的我怎么也能看见,为什么切了就清晰?」

**你的直觉对,我上一轮说的"差 6 倍"是错的,已作废。** 实测:

| | 长边 |
|---|---|
| 原图 | 中位 **1920** / p75 4032 / p90 5712 |
| 切片 | 中位 **1280** |
| preview 上限 | 1600 |

- 原图中位 1920 → preview 缩到 1600 是 **0.83x**,几乎不掉像素
- 切片中位 1280,**比 preview 上限还小** —— 切片在像素上根本不占优,常常更差
- 「查看原图」压根不走 preview,是**满像素**

那为什么感觉切了清晰?因为切片**占满屏幕**。同样的像素,在屏幕上更大。
**这是取景问题,不是分辨率问题。**

→ 于是解法出奇地简单,而且是整套方案的支点:
**显示原图,但自动缩放/平移到当前任务的框上。** 满像素 + 切片一样的取景。
这一下原图在每个维度上都严格优于切片,原图才有资格当唯一主态。

### ④ 「这套流程太乱了,我审核员怎么操作」

因为现在有 **7 个补救入口**(同图补小票 / 按店重切 / 追加图片 / 删除这张图 /
这其实是百货 / 改成护照 / 改成其他),而真实情况只有 **3 种**。收敛见下。

---

## 一、方案:一个视图,三个动作

> **审核台只有一个视图 —— 原图,自动对到当前任务的框上。裁剪只在交付时发生。**

这正是你说的:「都是原图,我直接定位到我的这个任务,护照也好小票也好。」

三种情况,三个动作,没有第四个:

| 你看到 | 你做 | 系统做 |
|---|---|---|
| 框对 | `Enter` 确认 | 交付时按这个框裁 |
| 框歪了 / 大了 / 少框了半行字段 | **拖一个新框** | 覆盖旧框,重读框内字段 |
| **少了一张单据**(4 张认成 3 张) | 在空白那张上**拖一个框** | 直接建一条新任务 + 按框重读字段 |

第三行是关键。现在这件事要走
「更多 ▾ → 同图补小票 → 跳过去 → 字段全手填 → 再去查看原图 → 再画框」**六步**,
收成**一个手势**。这就是你要的闭环。

## 二、分期

### P0 · 死路修复 —— ✅ 已上生产(`2d4fbad`)

做不到的按钮置灰 + 悬停给后端那句人话理由。灰阶不用红(红色会让人以为"点这里能解决",
而它恰恰不能)。规则的单一真相源留在后端,前端不复制。

### P1 · 主态翻转(最大收益,最小风险)

- 打开任务默认**原图**,并**自动 zoom-to-box**:算出让框填满视图的缩放,滚到框中心
  → 现成能力组合,`setZoom` / `applyZoomAnchored` / `stageRef.scrollLeft·scrollTop`
  都在,`recenterAfterRotate` 已经在做同一类事,**不用新基建**
- 「看切片」降为次要按钮(保留,做兜底和对照)
- 当前任务的框:红色实线常显;兄弟框:灰虚线,默认关,一键开
- **不动任何数据、不动识别、不动交付**

这一步直接消掉 ③,和 ④ 的大半 —— 因为"要不要切换视图""为什么切片更清楚"这两个
让人迷惑的选择本身就没了。

### P2 · 一手闭环(解 ①(b))

- **拖框 → 后台只对框内调一次 qwen 读字段 → 回填**
  (字段本来就是从整图读的,给它一个框读一个区域是同类调用,不是新能力)
- 空白处拖框 = **建任务 + 读字段**,一个手势
- 框改了 → 交付护栏那条红橙提示当场消失(现在也会,但要刷新)

### P3 · 收控件(解 ④ 剩下的一半)

| 现在 | 收敛后 |
|---|---|
| 同图补小票 | **删掉**(空白处拖框代替) |
| 按店重切 | 改名「换店重新识别」,从"框问题"路径移走 |
| 追加图片 | 保留(它是**传新图**,和框无关) |
| 删除这张图 | 保留 |
| 改成护照/其他/这其实是百货 | 保留(分类,不是切图) |

票号重复(实测 0.506%)给一个直达的「删这条」,不再让人自己找。

### P4 · 键盘可达

整条流水线是键盘驱动的(`Enter` 确认 /`R` 重拍 /`1·2·3` 原因),
**框选是唯一必须摸鼠标的东西**,这本身就是"乱"的一部分。
给:`B` 进画框态 / `Esc` 退 / `Backspace` 清框。

## 三、这套方案解决不了的(说清楚,别指望)

1. **qwen 把两张票框成一个框** → 系统不会自己发现"这个框里其实有两张",
   得你看出来、手拆成两个框。方案把"改"变简单了,没把"发现"自动化。
2. **完全漏掉、而且你也没注意到的票** → **没有任何机制会提醒你"这张照片上还有第 4 张"**。
   这是本方案的真实上限。
   要碰它得另做一件事:按「框覆盖面积占照片比例」把偏低的图挑出来强制人工复看。
   —— 建议做,但它是独立的一件事,不塞进这个方案。

   > **⚠️ 0731 实测:这个判据不成立,别照着做。**
   >
   > 拿本地 111 张照片量了一遍(覆盖比 = 各框面积之和 / 整图):
   >
   > | 分组 | 张数 | 覆盖比 |
   > |---|---|---|
   > | 单框照片 | 83 | 0.195 ~ **1.000**,中位 0.442 |
   > | 两框(切对) | 2 | 0.448 / 0.476 |
   > | 三框(切对) | 1 | 0.381 |
   > | 模拟"漏掉一张"(从切对的图里去掉一个框) | 3 | 0.221 ~ 0.265 |
   >
   > 三组**完全重叠**,全局阈值挑不出漏切。
   >
   > 而且这不只是样本不够 —— 逻辑上就不成立:**一张照片只有 1 个框时,
   > 覆盖比就是 1 个框的量,不管它是"本来就 1 张票"还是"2 张漏了 1 张"。**
   > 总覆盖比这个量天然分不开这两种情况。真正的差别在"**没被覆盖的那块地方,
   > 够不够放下一张和已找到的票差不多大的票**",那是个局部问题,不是总量问题。
   >
   > 换句话说,要做「第二眼」得换判据(见 todo #44/#52),
   > 而不是给覆盖比调阈值 —— 调多少都会把大量单票照片误报进来。
3. **原图不在盘上的那批** → 只能留切片兜底。比例**待测**(见下)。
4. **存量图没有字段框坐标**(换 qwen 之前的数据)→ 「当前字段」高亮对老图仍然是灰的。

## 四、待测的一个数(会影响 P1 的落地范围)

P1 要成为**唯一**主态,前提是每条任务都能同时拿到「框 + 原图」。

- **框**:已知基本满足 —— 51371 条小票只有 6 条无框(交付护栏实测,0 误报)
- **原图在盘上**:**未测**。「按店重切」的已知前提是"客户库原图还在,
  工作区被重传/清理过就没有"——所以这个比例一定小于 100%,但不知道小多少。

这个数决定 P1 是「唯一主态」还是「主态 + 切片兜底」。
两种都能做,差别是要不要保留切换按钮。**我倾向不管这个数是多少都保留兜底按钮** ——
成本一个按钮,收益是原图缺失时不至于无图可看。
