## 1. 现状全链路摸底(实证)

### 1.1 页面与路由

| 现状 | 说明 |
|---|---|
| `/` → `views/OverviewView.vue` | **所有角色共用一个首页**,只靠局部 `v-if` 区分(收票员看板仅 admin/finance 渲染)。区块:问候+快捷入口 / 新建批次横幅 / 今日待办·今日进度·本月进度三卡 / 收票员看板 / 待我处理 / 已完成批次 |
| `/admin/dashboard` → `AdminDashboardView.vue` | 系统健康仪表盘(内存/日志/模型/阶段任务),**运维视角,与本次无关,保留不动** |
| `/review/:batchId?tab=image\|field` | 审核页,admin+reviewer 可进 → "进入▶" 的落点 |
| 侧栏 `AppSidebar.vue` | 「工作台首页」指 `/`,无需改 |

### 1.2 数据链路(首页现在拉 3 个接口)

```
GET /api/workbench/overview   workbench_overview_routes → workbench_overview_service
  ├ today.todo      {preprocess, review, remedy}            实时积压,按操作员过滤
  ├ today.progress  {uploaded, reviewed, remedy,            ⚠️只统计"今日(KST)新建的批次"
  │                  completionRate, exportedFolders}
  ├ collectors[]    {owner, batches, collected, reviewed,   仅 admin/finance 返回,
  │                  pending, completionRate}               reviewer 拿空数组
  └ month           {received, unreceived, matched, ...}    月度对账段

GET /api/my/todos             my_todo_service(按角色 stage + 操作员过滤)
  └ todos[] {batchId, batchName, pendingCount, primaryStage, stages[], updatedAt, totalFiles}
     → 审核员「我的批次」的现成数据源,自带跳转 route(view+tab)

GET /api/state                workbench_state_service → listBatches → summarizeBatch
  └ batches[] 摘要 {id, name, createdAt, updatedAt, ownerUsername, monthlyWorkspaceKey,
                    machineState, groupCodeStatus, recognitionProgress,

     admin=全部批次 / reviewer=只有自己的(lib/operator_scope)
     带 mtime 摘要缓存 + 列表 TTL 缓存(workbench_batch_repository)
```

### 1.3 关键事实(决定字段能不能算)

- **`task.reviewedAt` 存在且可靠**:审核通过时写 ISO 时间戳(`services/workbench_write/task.js:315`),取消审核清空。→ "今天真正审掉多少张 / 批次审完时间 / 耗时 / 效率"都**可以精确算**,但目前**没上浮到批次摘要**。
- **任务没有 `reviewedBy`**:审核人归属只能按批次 owner 推(reviewer 只能审自己的批次,归属≈准确;admin 代审会记到 owner 头上)。
- **导出零留痕**:全库 grep 无 `exportedAt/exportStatus`;audit_middleware 只盖 登录+月度操作,批次导出(`/api/batches/:id/export` 及 3 个交付包导出)不留任何记录。→ "今日导出/导出状态/待导出"**当前无法成立,需新增落盘**。
- **用户表没有"工作区/员工编号"**:users = username/role/display_name/agent_code。"①区②区"概念**不存在**;批次上只有 `monthlyWorkspaceKey`(月份,如 2026-07)。
- **counts 里现成的异常桶**:`error`(OCR/流程失败)、`rephoto`(标记重拍=待补图)。"超时未处理"无定义。
- **技术栈**:Vue3 + Tailwind + 自建 ui 组件(shadcn 风格:`table/badge/status-badge/tabular-number/...`),**不是 React/AntD**。方案不引入 Ant Design 依赖,用现有组件体系复刻其视觉(卡片/圆角/蓝白/Progress)。

### 1.4 提示词字段 ⇄ 现状核对表

| 提示词字段 | 现状 | 结论 |
|---|---|---|
| 今日上传 | `today.progress.uploaded` | ✅ 现成 |
| 今日审核 | `progress.reviewed`=今日**新建批次**的已审数,昨天批次今天审的不算 | ⚠️ 需按 `reviewedAt∈今日` 重算(P0) |
| 今日导出 | 无导出留痕 | ❌ 需新增 `exportedAt`(P1) |
| 今日异常 | `counts.error + counts.rephoto` 可聚合 | ⚠️ 口径待拍板(§6-2) |
| 今日完成率 | `progress.completionRate` | ✅ 现成(口径=今日批次) |
| 看板:收票员/批次数/收图/已审/待审/完成率 | `collectors[]` 全有 | ✅ 现成 |
| 看板:工作区 | 用户无此概念 | ⚠️ 待拍板(§6-1) |
| 展开→该员批次+待办+进入 | `/api/state` admin 全量批次含 owner,前端分组 | ✅ 可推导 |
| 已完成批次:完成时间/耗时 | 摘要只有 createdAt/updatedAt | ⚠️ 需上浮 `lastReviewedAt`(P0) |
| 已完成批次:导出状态 | 无 | ❌ 依赖 exportedAt(P1) |
| 异常提醒:OCR失败/待补图 | `counts.error` / `counts.rephoto` | ✅ 现成 |
| 异常提醒:超时未处理 | 无定义 | ⚠️ 可推导:有待审 && updatedAt 距今>阈值(§6-4) |
| 异常提醒:待导出 | 审完未导出 = pending==0 && !exportedAt | ❌ 依赖 exportedAt(P1) |
| 审核员:今日完成/今日效率 | 需 reviewedAt 按日聚合 | ⚠️ P0 完成数 / P2 效率 |
| 审核员:当前排名 | 可服务端算(只回名次,不回他人明细,不破坏隔离) | ⚠️ P2 可选(§6-6) |
| 审核员:本月完成/平均速度/完成率/返工率 | 无个人月度统计;"返工"无事件史 | ⚠️ P2 近似口径(§6-5) |

## 2. 架构决策

1. **一个路由,两个页面组件**。`/` 挂 `HomeView.vue`(纯分发器,按 `auth.user.role` 渲染),拆出:
   - `views/home/AdminHomeView.vue` — 管理员(finance 复用,只读同款);
   - `views/home/ReviewerHomeView.vue` — 审核员。
   现有 OverviewView 单页 v-if 已经在分叉,两个身份的信息架构完全不同,继续揉在一起违背"彻底分离"。**月度三卡(本月进度)从首页退位**:管理员版收进一张次要卡或仅留入口,审核员版彻底不出现(提示词:不展示管理员统计)。
2. **后端仍然一个聚合接口**,扩展 `GET /api/workbench/overview`,不开新端点:
   - `today.reviewedToday`(全体/按人):Σ reviewStats.reviewedByDate[今日];
   - `collectors[]` 追加 `reviewedToday / uploadedToday / errorCount / rephotoCount / staleCount`;
   - `alerts {ocrFailed, stale, rephoto, unexported}`(管理员异常提醒行);
   - `me {reviewedToday, rank, total}`(审核员 KPI;rank 服务端算,只下发名次)。
3. **`summarizeBatch` 上浮审核时间统计**(`lib/workbench_batch_response.js`):
   `reviewStats: { firstReviewedAt, lastReviewedAt, reviewedByDate: {"2026-07-18": 210, ...} }`
   纯函数于 batch.json 内容 → **摘要 mtime 缓存安全**;"今日"判定放在 overview service 请求时(KST,复用 `businessDate`),不烤进缓存,跨天不脏。
   - 完成时间 = lastReviewedAt(pending==0 时);耗时 = lastReviewedAt − createdAt。
4. **导出留痕(P1)是唯一的新落盘字段**,走全套铁律:
   - batch.json 加 `exportedAt / exportedBy / exportKind`;
   - **三处同步**:`lib/field_registry.js`(FIELD_CONTRACT 登记)→ `lib/workbench_normalizers.js#normalizeBatch` 白名单 → `summarizeBatch` 透传(前车之鉴:owner 三件套被 normalize 抹掉的隐形 bug);
   - 写入点:`/api/batches/:id/export` + 3 个交付包导出 handler,**必须在 `withBatchWrite` 锁内**;
   - `lib/audit_middleware.js` 补 batch export 路由映射(action: `export_batch` / `export_delivery`),今日导出数从审计表算,重导不重计。
5. **不引 AntD**。新建 `components/home/` 复用现有 ui 体系:`KpiCard.vue`、`ProgressBar.vue`(绿色完成率,统一替换现有 3 处手写 progress)、`CollectorBoard.vue`(排序+搜索+展开行)、`BatchListTable.vue`(管理员已完成/审核员我的批次共用)。数字右对齐用现成 `tabular-number.vue`。
6. **排序/搜索/展开全部前端本地做**:collectors 20~30 人、批次几十个,一次全量下发,不加分页接口。

## 5. 风险与护栏

1. **落盘字段铁律**:exportedAt/reviewedBy 若漏 normalize 白名单 → 存盘即抹(owner 三件套前车之鉴)。三处同步 + 回归测试是硬条件。
2. **摘要缓存**:reviewStats 必须纯函数于文件内容;任何"今日"判定禁止进 summarizeBatch。
3. **月度个人统计的地基**:基于现存批次算,批次删除/清理后数字会缩;P2 文案标注"按现存批次",要精确需等审计事件流(不在本期)。
4. **admin 代审归属**:今日审核按批次 owner 记账,admin 代审会算给 owner——P2 的 reviewedBy 才能根治,先在文档口径里写明。
5. **导出并发**:exportedAt 写入必须走 `withBatchWrite`,否则与审核写并发互吞(批次写锁铁律)。
6. **兼容**:`/api/workbench/overview` 只增不改删,旧字段(month/today.progress)原样保留,月度卡挪位不影响其他页面。
