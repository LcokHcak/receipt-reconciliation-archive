# 同步一致性审计(2026-07-16)——"改一处,相关的都跟着变吗"

> 用户命题:任何 增/删/改 发生时,所有相关数据/口径是否保持同步一致。
> 方法:三域并行代码实证审计(配置变更域/审核数据域/台账账单域),每条链给证据 file:line + 有无测试锁;
> "钱"级发现由主会话二次抽查坐实。共 **实证 GAP 16 条**(A级4/B级6/C级6),健康链 20+ 条(多数有机器锁)。

## 一、先说健康的(这些"改了确实会跟着变",且有测试锁)

## 二、A 级(影响钱/交付内容,建议必修)

**A1 人工匹配结论不抗 bill_match 重跑(绕锁)**
`bill_match/index.js:152-175` 每次重跑 clearCurrentMatchOutputs → `resetBillMatchForIds`(writes.js:605-611,**裸 UPDATE 不查 manual_locked_fields**,主会话已抽查坐实)把人工 resolve 锁下的 matched 打回 unmatched + matched 日志删除;引擎重匹配想写回又被锁拦;冲突依旧时指纹去重(resolved 压制)不再立项 → **人工匹配结论丢失+月度行丢失,无人知晓**。修:resetBillMatchForIds 尊重锁(锁行跳过+保留其日志),或人工 resolve 的日志标 protected 不入 clear 集。

**A2 monthly_data 两条重建路径口径分裂(单行重建缺钱字段)**
merge 全量(merge_streaming_service.js:390-528)=daily+账单回填+**calcCustomerRebate 返点**+merge_config_version;resolve 单行重建(pending_review_resolution_service.js:409-452)**只拷 daily 字段,返点=null,无账单回填**,hashRow 还多混 updatedAt(:473-480,主会话抽查坐实)。resolve 后若无人标脏 merge,**交付直接用缺返点的行**。修:单行重建复用 merge 的行构造(抽共享函数),或 resolve 后强制标脏 merge。

**A3 listing_routes 手改/人工补救不标脏**
台账手改 PATCH(listing_routes.js:244-252 含人工补救直标 matched)/行删除/pending resolve/手工补录——**全程无 markDirty**(grep 坐实仅 4 个路由文件有标脏)。人工补救成 matched 的行**不进 monthly_data**、改值不刷新导出,直到别的事件恰好标脏该月。同功能的冲突 tab 入口标了 merge 脏——两入口口径不一。修:这四处补 markDirty(便宜,状态机现成)。

**A4 导出计划 scope 匹配口径分裂(别名/尾巴票静默漏出交付)**
冲突检查把 scope.modes canonical 化(config_console_routes.js:351);**运行时全裸串精确比对**:DSL 引擎(export_plan_engine.js:212-223 比 modeRawPre 原串)/资料库卡片适用性(library_delivery_routes.js:263-264)/Excel queryLedgerRows(workbench_server.js 无别名桥)。团号表别名写法/带尾巴串的票 → 判不在 scope → **整客户组静默出包,冲突检查却说没问题**。修:三处 scope 匹配统一双方 resolveCanonicalModeName 后比对。

## 三、B 级(静默丢数据/一致性,建议尽快修)

**B1 normalize 白名单落网 4 字段**(审核域主发现)
`autoSplitRole/preprocessMessage/preprocessWarning`(workbench_task_factory.js:151-153 写入;投影 isOriginalLikeTask customer_projection.js:127-131 消费——**批次重存即被抹→投影计数漂移**;前端"原图/切图"命名退化)+`classificationSource`(统计用)。均不在 workbench_normalizers 白名单、未登记 field_registry,契约守卫抓不到——owner 隐形 bug 同款病理。**连带**:rebuild 读原始 JSON、增量链吃归一化对象 → 同一批次两路径算出不同覆盖层(S9 分叉),parity 只比行数发现不了。修:4 字段进白名单+registry 登记(小时级,机器守卫即刻锁死)。

**B2 tour_match 自愈越界删(=上次审计 M4,这次确认更严重)+second_pass 无去重**
tour_match_service.js:99-116 两处 deleteOpenBySourceIds 无 reasonType 过滤——**每次流式结算触发的增量 tour_match 都在扫掉** open 的 second_pass_candidate(不只换表重跑);且 second_pass_missing_service.js:101 直插无去重,重跑堆积(目前被误删"对冲"掩盖——修 M4 必须同时给 second_pass 补去重,否则揭开盖子变堆积)。

**B3 删台账行不清 store_bill 侧待审**
级联只清 source_table='daily_receipt_export';field_conflict/ambiguous/fuzzy 挂在 store_bill 名下(dailyReceiptId 在 detail 里)→删行后残留 open,resolve 时 daily_not_found 保持 open(H3 新口径下**永久卡住**),活跃阻塞谓词也排除不了。修:级联补 json_extract 清理(有 closeFieldConflictByDailyReceiptId 先例)。

**B4 账单 row_hash 是位置哈希(混 sheet 名+行号)**
bill_mapper.js:68,220——新版账单文件插/删一行→其后所有行全新 hash;**不清桶直接导新文件=旧新并存→同台账行双 matched 日志→月度双计**,系统不拦。短期:操作规程强制"改账单必走桶级替换";长期:改业务键哈希。

**B5 删除入口缺已审/已结算闸**
deleteTask 零拦截(对比 resplit 有 409 先例)——已结算票可静默删,台账 source_task_id 悬空+证据图物理删除;deleteSourceGroupCustomer forceRemove:true 绕过已审闸(前端只用于重复建档场景,但后端无闸);deleteWorkspaceCustomer 对已审组"客户删了批次任务留着"半删状态。修:补 409 闸(照 resplit)。

**B6 已启用计划硬冲突漂移**
冲突检查只在计划 save/activate 时跑;**后改基线/店档案不重检 active 计划**→时序绕过"硬冲突禁启用"闸;emptyPolicy=skip_log 的计划会**静默跳票**交付缺文件。修:基线/店档案保存响应附带受影响计划警告(复用 computePlanConflicts 只读不拦)。
