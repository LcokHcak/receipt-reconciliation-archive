**一句话**:今天没做新功能,做的是**把系统里"算出了问题却没人看见"的地方全部翻出来**。

## 一、起因:一个 bug 牵出一整类

早上从一个具体问题开始——**乐天百货交付包的护照打码,从上线起就从没生效过**。

顺着查下去发现它不是孤例,而是一个**反复出现的形状**:

> 系统算出了「这条数据没进去 / 没处理成」的信息,然后把它扔了,没人知道。

于是把三条主干链路各扫了一遍。

## 二、三条链的排查(共修 15 处)

### 交付链(7 处)—— 决定"谁拿到哪些图"

| 问题 | 后果 |
|---|---|
| 未审完的客户组整组跳过 | 0722 那批**静默少发 3 个客户组** |
| 护照打不了码的图 | 上家收到**未遮盖的护照**,无人告知 |
| 「不用记」的票账不进单、图进包 | 包里图数比账单行多,**对账对不上** |
| 源图取不到的四处裸 `continue` | 包里少图,**兄弟服务早有名单,唯独这个文件漏了** |
| **护照图丢失被误报成"客户没交护照"** | 交付说明叫上家「回报姓名」,**上家照做也补不出来** |
| 月度最终交付的七类异常只写进包内 JSON | 前端看到的是**一张干净的成功页** |
| 现代包 / 客户文件夹包 / 配置台计划无任何说明 | 同上 |

**统一做法**:六个导出入口全部补上包内「导出说明.txt」,写清**少了什么 + 为什么 + 下一步**。
刻意做了一件事:**正常情况也要说明它是正常的**(例如「未收补录客户不出 PDF,属正常」),
否则每次都被当故障查一遍。

### 结算链(5 处)—— 决定"谁拿多少钱"

**整体健康,零个严重问题**。团号匹配、账单匹配、未收清单、数据库层去重都已有可见出口。
但抓到一条在**天天走的路**上:

- **撞票号的票被静默丢弃**。系统按「店+票号+购买日」拦重复(数据库口径也如此,**不看客户**)。
  整组都撞会报出来,但**组里只有部分撞时,那张票悄悄扔掉、该组仍显示"导入成功"**。
  而这个撞键**不是良性去重,是数据错误的信号**——同店同日同票号只能是一笔交易,
  两个客户都有,只可能是票号读错或建档串了客户。被丢的那张不进台账 = **少一笔返点**。

另外三条:代理归属查询的空 `catch`(服务故障和"查无此人"混为一谈)、
团号匹配取不到行时纯 `continue`(那行**永远停在 pending 且人工补救界面也捞不出来**)、
合并阶段的丢弃计数一路被丢(服务算了 → 调用方没接 → 界面零痕迹)。

### 收图链(3 处)—— 决定"票有没有进系统"

- **重识别回灌失败,前端一个字不看**。后端注释写着「报错误让操作员用补图自愈」,
  但界面不管成败都弹「已提交」。新切出的图(**可能正是那张漏切的护照**)留在客户库,
  **永远不会变成审核任务**——这正是 0722「缺护照」事故的复现路径。
- **共享 Excel 读取器缺 sheet 完整性守卫**。同一个"静默丢整张 sheet"的 bug
  在另外两处**各自修过**,唯独共享的那个没有,而 5 条导入路径全走它。
- 批次记录损坏时跨工作区护栏被短路跳过,客户**悬在库里、永远进不了审核队列**。

## 三、护照识别:两道闸(全天最严重的一条)

跨图纠正的规则是"某护照号出现 ≥2 次即采纳"。生产数据实测:

- 3786 条纯共识改写里,**2063 条写入的值是 OCR 残串**(`E`、`494`、`CHNE951`、`CHNEQ72`)
- 其中一批还被标成「不用复核」,**388 条与人工确认的护照号直接冲突**

**成因很实在**:免税店小票上**印着**护照号,同一台 POS、同一字体,
OCR 很可能把两张小票**同样地读错**——两票错读压过护照图那一票正读。

修了两道闸:形态不合法的候选**没有投票权**;值被弱证据改写的**必须留在复核队列**。

## 六、我自己犯的三次错(都被生产数据打回)

这三次值得单独列,因为教训比修复本身更有用。

1. **合并告警**:一度把 2823 行「归不到交付桶」全报出去 —— 量化后 **98% 是设计正确的越界**
   (百货本就不走四桶)。若发出去,操作员三天就学会无视告警。
2. **Excel 截断**:看到 1,048,574 行就断定"源文件被截断、账少一截" ——
   查实是**空行撑的**,真实数据只有 15,204 行。文件完全正常。
3. **护照形态闸**:写死大陆格式 `[A-Z]{1,2}\d{7,8}` —— 会**误伤台湾客人**
   (台湾护照是 9 位纯数字,姓名 `CHOU HSUEHHSIN` 这种威妥玛拼音是唯一线索,
   而它只存在于数据里)。已改成按结构判定。

**共同的根**:先按脑子里的模型下结论,再去找证据。

## 七、沉淀下来的判据(已写进项目档案)

**关于"静默失败"**
1. `logger.warn` / `console.warn` **不算告知** —— 操作员看不到服务器日志
2. 返回值里的名单**若调用方不消费,等于没算**
3. 二进制流接口(`res.download`)没法用响应字段告知,**只能把话写进包里**
4. **「其余照常处理」型注释是高危信号** —— 照常没错,但被跳过的那些去哪了要有交代

**关于"加提醒"**
5. 加提醒前先问:**它在健康的生产数据上会不会亮?** 会亮就说明口径错了
6. **严重度不能靠读代码估,只能在生产数据上数一遍**(今天两个方向都错过)

**关于测试**
7. 规则类逻辑**必须有一条真的执行它的测试**;源码字符串断言锁不住"它还能不能跑"
8. 测试夹具要照**生产真实产出的形状**搭,照代码分支搭会测出假安全感
9. **写完防回归测试,先把代码改回坏状态跑一遍,红了才算数**
   —— 今天做了这步的每一次都立刻抓到问题,唯一漏做的那次就是事故本身

**关于工具**
10. 批量静态分析**必须先用一个已知答案校准**;今天我的扫描脚本连续四版都是错的,
    报过 22 / 7 / 1 个"越权漏洞",真值是 **0**
11. **「几乎可以肯定」四个字,就是没查完的意思**
