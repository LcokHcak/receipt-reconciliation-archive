# 识别提升二批:90% 冲刺选型(2026-07-21)

承接一批(f4b81a6,P1-P3)。目标:票号准确率 90%。本批新增**生产代表性随机样本**
(一批的 94 张是错例偏置,只能证明"修得动",量不出绝对准确率),多方案实测选型。

## 一、随机 stage2(tmp/errfix_stage2,80 张)

近期批次(≥07-04,当前 prompt 时代)按生产店量配比、md5 哈希可复现抽样,不看对错:
乐天 20 + 济州 8 + 新罗 16 + 爱宝客 10 + 新世界 16 + 现代 10。金标票号位数正常域才收。

**重要方法论发现:重放喂任务切片,生产管道从整图抽字段——切片把票号头部几位切糊,
重放绝对值系统性低于生产条件**(同代码:重放 65.5% vs 生产原值 77.5%)。
因此:变体间对比看重放(同输入公平);冲 90% 的投影以生产原值为底、
叠加"生产错例被新机制翻正"的实测下界。

## 二、新增改动(在一批锚点+二遍机制上扩展)

1. **新罗系锚点**(挖矿实测,5728+1874 张 Final):13 位、前缀新罗 01/03(99.6%)
   爱宝客 21(99.7%)、第 3-4 位=购买年份后两位(99.0%/99.6%)。
2. **二遍重读扩五店**,repair prompt 按店分文案(乐天 14 位 6-2-6/新世界现代 16 位
   2-6-3-5 嵌日期/新罗系 13 位 2-3-3-4-1),版本 v1→v2。
3. **全量双读模式**(QWEN_RECEIPT_NO_REPAIR_MODE=always,新默认):启用店每张小票
   裁上部放大读第二遍——两遍一致=互证通过(实测 29/30 全对);不一致且一遍锚点全过
   =保一遍值+`receipt_no_second_pass_mismatch` 红标(分歧保一遍实证 8:3 优于换二遍);
   一遍锚点未过=沿用一批采纳规则。锚点触发档(anchor)保留为省钱降级项。

## 三、选型数据(80 张随机样本,加权=生产店量占比)

## 四、代价与旋钮(部署要知道的)

- always 双读:小票预处理调用约翻倍(裁片小图 token 少于全图,实测 80 张 89→170 调用),
  API 成本估 +40% 上下(¥2100/月 → ~¥3000/月),单图延时 +8~10s;
  TPM 吃紧就 `QWEN_RECEIPT_NO_REPAIR_MODE=anchor` 降到 +29%(投影 87.3%)。
- 双读分歧红标约占小票 20%+(其中约半数一遍本来就对)——是引导不是负担,
  审核员看红标优先;`receipt_no_second_pass_mismatch` 文案已进前端。

## 五、诚实边界

- n=80,店内子样本 8-20 张,投影 ±5pp 级噪声;**90.3% 是压线不是安全垫**。
  硬结论要靠部署后跑错误矩阵(全量金标,零成本)复核。
- 重放-生产输入条件差已识别(切片 vs 整图):后续金标重放若要量绝对值,
  stage 应收原图而非任务切片(本批已在文档留此改进项)。
- 双读对"两遍同错"(系统性混淆)无解;济州 906/90G 类金标噪音仍在,矩阵读数略高估错误率。
- 天花板选项未动:条码本地解码(零 API 的地面真值)、qwen SFT 微调(4.5万金标对可作训练集)。
