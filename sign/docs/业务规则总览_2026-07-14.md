### 百货护照口径(2026-07-14 拍板)

- **纯百货组(组内小票全是百货)可整组无护照 → 全链放行**(通过/结算/归档)。
  归档文件夹保留建档原名(没有 姓名_护照号 可拼),账单身份留空。
  - 细化(复核收口):豁免只对**新世界/现代**(票面本就无护照,档案旗标 `passportFree`);
    **乐天百货**是护照同框票,组里没独立护照时**票上必须有身份**(一张带上即可,系统会
    自动传给同组兄弟票)——否则乐天交付包的"护照图"没有来源,会堵整批交付。
- 组里有护照 → 结算时身份自动从护照传播到百货台账行。
- **混合组**(百货+免税小票同组)→ 免税部分离不开护照,仍要求身份兜底。
- 一组 **2 本以上不同护照号** → 仍拦(两人证件混放会取错)。
- 真相源:`lib/validation/group_passport_rule.js`(单一真相源,通过闸/结算/台账导入/前端全部调它)。

## 五、审核流程(票级两步流)

1. **护照必审**,永不免审。
2. 小票**表态三件套**:已匹配(命中团号表)/ 无团号直接确认(机场票)/ S活动人工标记。
3. 组内排序:护照 → 小票 → 其它;整组表态完出**回执卡**(客户X:收到N张小票,模式×N)。
4. **一号多渠道**(同团号两家代理):系统绝不默取,必须人工点选。
5. **团号对得上但表里登记别家店**(tour_store_mismatch):黄徽章提醒核对。
6. SLIM 免审车道(灰度,默认关):模式在 ENV 白名单 + 团号命中 + 人工表态,三条件缺一不可。
7. **确认合并结算**:整组审完自动 通过+结算,弹模式面板确认渠道模式。
8. 结算前**日期预检**:购买日期超窗/非法在不可逆操作之前拦下。

## 八、重复客户与二次收票判定(2026-07-14 现场拍板)

**判重主键 = 护照号 + 小票号/交易编号**,比对用**数字投影**:`5801-0110` 与 `58010110`
是同一张票(带杠只是票面/导出形态,百货台账存带杠、免税店存纯数字,两侧投影后再比——两类通用)。

⭐**百货和免税店小票分家处理(2026-07-14 拍板:类型不一样,处理方式不一样,不要混)**:

| 场景 | 纯百货组 | 含免税店小票的组 |
|---|---|---|
| 同客户再来一组,**票号全新** | ✅ 二次收票 `_2/_3…` 放行 | ✅ 二次收票 `_2/_3…` 放行 |
| 一组里**老票+新票混着** | ✅ 放行(多笔交易常态;已入账票由台账行级去重兜底) | ⛔ 拦(重传老票=操作失误,早拦早清) |
| 组里**所有票都已入过台账** | ⛔ 拦:报撞的票号+删除按钮 | ⛔ 同左 |
| 同一张票换形态再交(带杠↔纯数字) | ⛔ 数字投影视为同一张 | ⛔ 同左 |
| **归档后缀上限** | `_2.._99`(同客一天多次归档常态,不再报"同名归档过多") | `_2.._9`(超过=异常密集,人工看) |

**队列显示口径**(同日拍板):审核中心左侧组名**恒显代理名**(customerAgentName);
结算归档会把客户档案显示名改成"英文名_护照号"(交付命名需要),该改名**不再泄进队列**。
真相源:`services/customer_finalize_service.js`(归档分流)/ `frontend/src/lib/reviewDisplay.js`(队列组名)。
