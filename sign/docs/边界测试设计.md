# 边界测试设计文档 — Passport Sign Batch(护照签字批处理)

> 目的:系统性梳理核心业务域的**操作 → 逻辑分支 → 边界条件 → 测试用例 → 现有覆盖/缺口**,
> 作为补齐边界测试的施工蓝图。先设计(本文档),确认形式后再补测试代码。
>
> 状态:🚧 四域深挖中(2026-07-21 起草),本节先立骨架,各域内容由深挖结果填充。

## 组织约定

- **按业务流程分域**,不按代码文件——边界问题是业务语义的(团号命中/无团号、护照 0/1/2 本、
  日期越界、百货三家、模式映射…),这样清单对得上业务,也便于逐域交付。
- 每个操作按统一格式:
  - **分支**:该操作的所有逻辑路径(正常 / 各异常 / 各边界)
  - **边界条件**:业务语义的 edge cases(具体输入 → 预期结果)
  - **现有测试**:`tests/` 里已覆盖的分支(✅)
  - **缺口**:未覆盖的边界(❌ 高 / ⚠️ 中 / ▫️ 低)+ 一句话测试用例设计
- 覆盖标记:✅ 已覆盖 · ⚠️ 部分覆盖 · ❌ 缺口(需补)

## 主流程全景

```
收票建档 ──→ OCR识别 ──→ 审核台 ──→ 结算 ──→ 团号匹配 ──→ 台账 ──→ 交付导出
(域4)       (域4)      (域4)      (域1)    (域2)       (域1)    (域3)
  │                      │          │        │                    │
  └── 批次调度(支撑)      └─ 补救 ←──┴────────┘        配置台(支撑)──┘
                          (支撑)                        代理视图/账单匹配(支撑)
```

本轮设计覆盖四个核心域(基本是整条主链路):
- **域1 结算+台账桥** — 历史事故最密(Internal error / 双计 / 丢行),边界最需锁死
- **域2 团号匹配+无团号** — 命中/未命中/歧义/无团号不动点/团号表解析(F1/F1b 所在)
- **域3 交付导出** — 交付包/百货三家/S活动双份/上家链/预检阻断(F6 所在)
- **域4 审核台+百货+建档OCR** — 表态/字段必填/百货身份/上传格式/OCR 失败/切图

支撑域(补救/配置台/代理视图/账单匹配/批次调度)本轮不展开,列入后续。
