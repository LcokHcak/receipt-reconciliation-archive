# 收票对账系统 · 全流程操作手册(SOP)

> 版本:2026-06(对应导航重分组后的界面)。配套《UI字段说明-2026-06.md》一起看。
> 本手册按**真实先后顺序**写:建员工 → 建档收票 → 日度审核 → 异常补救 → 月度对账 → 交付。
> 每步标明:**在哪个页面、点哪个按钮、填什么、核对什么、怎么判断对错**。
>
> 角色:`admin`(管理员,全权)/`reviewer`(审核员,日审+月度)/`finance`(财务,看数+导出)。
> 四个桶(账单来源):**乐天首尔 · 乐天釜山 · 爱宝客 · 济州新罗**。

---

## 阶段 0 — 建员工(只有 admin 做一次)

**页面**:左侧栏 `系统管理 → 用户管理`(或 `/admin/users`)。

1. 点「新增员工」。
2. 填字段:
   | 字段 | 必填 | 说明 |
   |---|---|---|
   | 登录账号 username | ✅ | 登录用,英文/数字,唯一 |
   | 密码 password | ✅ | **≥6 位**,创建后让本人尽快改 |
   | 角色 role | ✅ | `admin` / `reviewer` / `finance`,按需给最小权限 |
   | 显示名 displayName | 选 | 中文名,界面显示用 |
   | 员工编号 agentCode | **收票员要填** | 形如「9号」。**收票汇总按这个分 sheet**,不填后面按员工分账会乱 |
   | 邮箱 email | 选 | 备用联系 |
   | 启用 isActive | — | 默认启用;离职改停用,别删账号(留审计) |
3. 保存。需要改密码:该员工行 →「重置密码」。

> ⚠️ 上线前:把默认 `admin/admin123` 改成强密码(见《上线前排查》P0-2)。

---

## 阶段 1 — 建档与收票(reviewer / admin)

**目标**:把每个客人的护照 + 小票图片归到一个客户档案,等待 OCR 识别。

**页面**:左侧栏 `日常工作 → 建档与收票`(`/intake`)。

1. 选/建本月工作区(月份 workspace,如 `2026-06`)。
2. **上传方式二选一**:
   - 整文件夹导入:一个客人一个文件夹(护照 + 小票放一起);
   - 单张上传:逐张选图。
3. 系统**自动分组**成批次(batch),按客户聚合。上传完进入「审核中心」。

**核对什么**:上传数 = 实际图片数;每个客人至少 1 张护照 + N 张小票。漏传的回这里补。

---

## 阶段 2 — 日度审核(reviewer / admin)

**目标**:核对 OCR 识别出来的字段,逐张确认/改正,通过后入台账。

**页面**:左侧栏 `日常工作 → 审核中心`(`/review/:batchId`,首页「待审核」数字也可直达)。

界面分三个 Tab(顶部切换):

### 2.1 图片确认 Tab(image)
- 看原图,确认**图片类型**分对没:`护照 / 小票 / 其他`。
- 分错的在这里改类型;废图标「其他」。

### 2.2 字段审核 Tab(field)— **核心**
- 左边图、右边字段。点图上的**定位框**会跳到对应字段。逐个核对(详见《UI字段说明》护照/小票字段):
  - 护照类:**英文名、护照号、中文签字名**。
  - 小票类:**免税店(LOTTE/THE SHILLA/SHILLA IPARK 三选一)、小票号、团号、购买日期、出境日期**。
- 改完每张点「通过」。识别可疑的会标黄,**重点核黄的**。
- 整批处理完,界面顶部出现「本批次已处理完」横条 → 点「导入日度台账」。

### 2.3 签字 Tab(signature)
- 需要签字的客人:确认中文签字名 + 选签字样式;或上传/手写签字。

### 2.4 批次级操作(右上「更多」)
- **导出当前批次客户数据**:把本批客人按「客户名 护照前4位」文件夹打包图片(不含账单 Excel),给下游用。
- **删除整个批次**:谨慎,不可恢复。

**核对什么**:通过数 = 文件数 - 废图;黄标全部处理过;台账导入后回不去就别急着导(先核完字段)。

## 阶段 3 — 异常补救(reviewer / admin)

**目标**:台账里**团号没匹配上**的行,人工补救。

**页面**:左侧栏 `日常工作 → 异常补救`(`/daily/remedy`,首页「待补救」数字直达)。

为什么会进这里:小票的团号/代理/购买日期对不上团号表,`tour_match_status` 落在:
`tour_not_found / tour_ambiguous / agent_mismatch / date_out_of_window / mode_unresolved / date_missing`。

**怎么补救**:
1. 逐行看红字提示(哪不对)。
2. 改正 团号 / 姓名 / 护照号 / 代理,或直接选**模式(mode)**。
3. 选了模式 = 确认重新匹配(`manualRemedyConfirm`),保存后该行重新跑匹配。
4. 批量:都内联选好模式后,点「一键补救」一次性提交。

**核对什么**:补救后「待补救」数字应下降;反复 `agent_mismatch` 的多半是代理别名问题(如 AYC=新琪),记下来反馈(暂无别名表)。

## 阶段 4 — 月度对账(reviewer / admin / finance)

进入:左侧栏 `月度工作 → 月度首页`(或右上角月份切换器选月)。
**月度首页只指路**:看「下一步建议」卡 + 三段进度,按提示进对应页。
下面是**标准顺序**。

### 4.1 数据库-台账(`ledger`)— 先看料齐不齐
- 审核通过的小票按购买日期进了本月台账没。
- **核对**:已收数量 ≈ 这个月实际收票量;缺的回阶段 2 补审。

### 4.2 账单匹配(`bill-match`)— 四个桶导账单 + 跑匹配
1. **按桶导入账单 Excel**:乐天首尔 / 乐天釜山 / 爱宝客 / 济州新罗,各导各的。
   - **替换本桶**:清旧账单重导;**追加文件**:补充不清旧(同行按 hash 去重)。
2. 设**扣点表**(每个模式的返点扣点)→ 确认。
3. 设**模式归类**(账单模式 → 交付桶)→ 确认。
4. 跑匹配。**扣点表 + 模式归类两个都确认了**才能出报表(merge)。
- **核对**:看「台账匹配率 = matched/台账数」(台账是小票级,可到 100%);
  「账单明细覆盖 = matchedBillRows/总账单明细」是辅助指标(账单是商品行级,数值天然低,别慌)。

### 4.3 特殊活动(`brand-activity`)— 限时/品牌活动
- 处理限时活动类账单(会折进对应桶,含负数冲减)。业务 mode 仍叫「品牌活动」。

### 4.4 账单核对(`bill-review`)— 处理阻塞项
- 处理:**字段冲突、多候选、模糊匹配**(字段冲突 Tab 也在这页)。
- **核对**:把阻塞项清到 0 再往下;有冲突先在这解决。

### 4.5 手动录入(`manual-entry`)— 无图/补录
- 没有图片但要计入的:手填 模式/客户号/姓名/购买日期/护照/金额。
- ⚠️ **上线前注意**:此页当前用 mock 汇率/历史(见《上线前排查》P0-1),
  汇率口径定了再正式用,否则 USD/返点会错。

### 4.6 未收清单(`unreceived`)— 两类缺口
- **账单有、台账无**(客人买了没收到票)/**台账有、账单未到**。
- 逐条核销(`resolve`),支持批量。**核对**:能解释清每一条为什么未收。

### 4.7 最终核对(`delivery-check`)— 交付前体检
- 出报表前最后一道:健康检查 + 账单核对再刷一遍,确认没有卡点(`missing_rebate` 只卡匹配销售行)。

### 4.8 最终交付(`delivery`)— 生成 + 导出
- 「生成交付数据 / 出报表」→ 生成 `monthly_data`(走生产 `merge_streaming_service`)。
- 导出:交付 Excel(USD/KRW 汇总,定额舍入)+「收款凭证」PDF(留签字横线,**不放签名**)
  + 客户文件夹(命名 `客户名 护照前4位`)。
- **核对**:逐桶返点对标准答案;USD/KRW 汇总两边一致。

### 数据库类(随时查)
- **数据库-台账(`ledger`)**:本月所有台账行。
- **数据库-团号(`groups`)**:团号表(姓名/代理/日期匹配的依据)。
- **数据导入(灾备)(`imports`)**:出问题时的兜底导入入口,平时不用。

---

## 阶段 5 — 溯源 / 收尾
- **操作日志 / 审计日志 / Badcase**(`月度工作 → 溯源&日志`):出问题时查谁在什么时候改了什么、看坏样本。
- 月底归档:确认交付无误后,本月数据留档(不删账号、不删批次)。

---

## 一页速查(顺序记忆)
```
建员工(admin) → 建档收票 → 审核中心(图片/字段/签字→导台账) → 异常补救(补团号)
 → 月度首页 → 台账(看料) → 账单匹配(四桶导账单+扣点+模式→跑) → 特殊活动
 → 账单核对(清阻塞) → 手动录入(补无图) → 未收清单(核销) → 最终核对 → 最终交付(出报表+导出)
```

> 每一步「核对什么」记不住时:看首页三段(今日待办/今日进度/本月进度)的数字往下掉就是对的方向。
