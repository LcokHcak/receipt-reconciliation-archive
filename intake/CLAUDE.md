## 硬约束（不可违反）

1. **不在 `D:\JIN HAIMIN\self\ticket\` 下写任何文件**。本项目根目录是 `D:\JIN HAIMIN\self\intake\`。
2. **护照、姓名、护照照片属于敏感个人信息（PII）**。不得硬编码、不得明文外泄、不得发往境外模型。详见 [04-合规与数据安全规范](docs/04-合规与数据安全规范.md)。
3. **`intake` 不直接写 `sign` 的数据库**。只通过约定的数据契约交付，边界清晰。
4. **采集层必须是可替换适配器**。企微会话存档与 wxauto 输出同一种消息格式，上层不感知来源。

## 架构骨架（八层）

采集（企微会话存档 SDK / wxauto 备选）→ 接入（Express + OSS + hash 去重）→ 队列（Redis Stream）→ 理解（LLM 漏斗：轻量分类 + 多模态抽取 + MRZ）→ 编排（状态机 + 分组引擎，事件溯源）→ 数据（PostgreSQL，护照主键）→ 应用（审核后台 + 截止日告警）→ 集成（对接 sign）。

详见 [02-架构与技术栈](docs/02-架构与技术栈.md)。

## 技术栈

- 主语言 **Node.js**（对齐 sign）；采集器若用 wxauto 则 Python 独立进程
- 存储 **PostgreSQL** + **Redis(Tair)** + **OSS**
- AI **阿里云百炼 Qwen**：分类用 Qwen-Turbo，抽取用 Qwen-VL-Max；护照走 npm `mrz` 库
- 部署 阿里云 ECS / RDS / OSS，同 VPC，护照库独立 RDS + KMS

## 业务背景（理解消息必备）

- **流程状态机**：提交证件 → 申请挂团(SG/H/PKG/B团/V团等) → 员工回团号 → 客户购物 → 交小票 → 对账 → 返点。四个群验证流程一致，只是表达方式不同。
- **团号消息格式**（金矿，可正则）：`乐天B团号 26144790~6/12 EN7296496 SUN XIAO`，也有裸数字如 `2563`（需带会话上下文理解）。
- **分组三主键**：护照号（主）、航班号（副）、姓名（校验）。
- **一本护照 1:N 团号**（SG/H/PKG 各一个）。
- **截止日规则**：逾期小票无返点（如 6/1-6/2 小票收取截止至 6/8），是告警核心。
- **群分三类**：业务群（收票）、沟通群（皮肤科医美，另一条业务线）、点位群（折扣情报）。
