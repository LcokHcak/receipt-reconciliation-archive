# 04 · 合规与数据安全规范

> 本系统处理护照等敏感个人信息（PII），合规是硬约束，不是可选项。任何与本规范冲突的"省事做法"一律不采纳。

## 一、数据分级

| 级别 | 数据 | 处理要求 |
|------|------|----------|
| 高敏感 PII | 护照号、姓名、出生日期、护照照片、人脸 | 加密存储、最小权限、不出境、脱敏日志、可追溯访问 |
| 业务敏感 | 小票图、金额、团号、行程、客户消费记录 | 加密存储、按角色授权、留档审计 |
| 一般 | 群配置、规则字典、统计指标 | 常规保护 |

## 二、会话存档合规（企微主路径）

- **知情同意**：客户入群时企微会发送存档服务须知，默认同意；不同意者会被移出群。建群话术需提前与代理沟通，明确告知。
- **范围最小化**：只对必要的业务群开启存档；沟通群/无关群不纳入。
- **密钥职责**：RSA 公钥填企微后台用于加密，**私钥仅存于拉取服务，绝不入库/入 git/外发**。
- **可信 IP**：拉取服务器固定公网 IP 列入企微白名单。
- **时效**：存档数据仅 5 天可取，须及时拉取落入受控存储；落库后即按下述加密要求保护。

## 三、加密

- **传输**：全链路 HTTPS / VPC 内网；不走公网明文。
- **存储**：
  - 图片 → OSS **私有桶 + 服务端加密（SSE/KMS）**，禁止公共读，禁止生成长期公开 URL。
  - 数据库 → RDS 静态加密；护照库独立实例（与 sign 财务库分离）。
  - 密钥 → 阿里云 KMS 托管，应用通过 RAM 角色临时凭证获取，不落盘明文。
- **脱敏**：日志、审核界面默认对护照号/姓名做掩码（如 `EM93****78`），仅在必要操作时受控展示完整值并记录。

## 四、访问控制

- **最小权限**：RAM 子账号/角色按职责授权；处理服务、审核后台、运维各自独立角色。
- **护照数据**：仅审核与对账必要环节可访问完整值；普通查询只见脱敏值。
- **审计**：对完整 PII 的读取/导出留访问日志（谁、何时、为何）。
- **职责分离**：开发环境**不得使用真实护照/客户数据**；用脱敏或合成样本。

## 五、模型调用合规

- **不出境**：护照及任何高敏感 PII **只发往国内合规模型**（阿里云百炼 Qwen）或私有化部署；**禁止发往境外模型 API**。
- **数据使用**：确认所选模型服务的数据不用于训练（选择企业级/约定不留存的服务条款）。
- **必要性**：能用本地 MRZ 解析/规则完成的，不发图给模型。

## 六、数据保留与删除

- 原始消息与图片设定保留周期，到期按策略归档或删除（OSS 生命周期规则）。
- 提供按客户（护照号）删除/导出的能力，以应对合规要求。
- 删除前确认不影响在途对账；删除操作留审计。

## 七、Git 与代码安全

- `.gitignore` 必须覆盖：`.env*`、密钥/私钥（`*.pem`、`*.key`）、护照/小票图、真实客户数据、`data_sample/` 引用。
- 提交前扫描密钥；发现疑似泄露立即轮换并排查。
- 涉及认证/密钥/PII/外部 API/SQL 的改动，提交前过 **security-reviewer**。

## 八、与 sign 的边界

- `intake` 与 `sign` 数据库分离；通过受控数据契约交付，不互相直连对方明文 PII 存储。
- **不在 `ticket/`（含 sign）目录写入本项目文件**。

## 九、安全响应

发现安全/隐私问题：立即停止 → 用 security-reviewer 评估 → 修复关键项 → 轮换暴露密钥 → 全代码库排查同类问题 → 记录复盘。

## 十、上线前合规检查清单

- [ ] 业务群存档已获知情同意，建群话术到位
- [ ] RSA 私钥、各类密钥均在 KMS/环境变量，未入库未入 git
- [ ] OSS 私有桶 + 加密，无公开 URL；RDS 加密；护照库独立
- [ ] 日志/审核界面 PII 脱敏，完整值访问有审计
- [ ] 模型调用全部国内合规，护照不出境，确认不用于训练
- [ ] RAM 最小权限到位，开发环境无真实 PII
- [ ] 数据保留/删除策略与审计就绪
