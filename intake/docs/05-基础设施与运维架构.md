# 05 · 基础设施与运维架构

> 02 讲的是逻辑/应用架构（系统怎么跑）；本文件讲**正规项目落地必须的工程化与运维架构**（存储、备份容灾、审计、可观测、安全基建、CI/CD、容量、SLA）。面向"能长期稳定、可审计、可恢复"的生产标准。

## 一、环境分离

| 环境 | 用途 | 数据 | 隔离 |
|------|------|------|------|
| dev | 开发 | **合成/脱敏样本，禁真实护照** | 独立资源 |
| test | 自动化测试 | 固定样本 + 385 回归集（脱敏） | 独立 DB/桶 |
| staging | 预发，贴近生产 | 脱敏或小流量 | 独立 VPC 子网 |
| prod | 生产 | 真实数据 | 独立 RDS/桶/RAM 角色 |

- 配置、密钥、数据库、OSS 桶**按环境物理隔离**，绝不混用。
- 生产数据**不得下行**到低环境；调试用脱敏导出。

## 二、存储架构

### 2.1 关系库（RDS PostgreSQL）

- **护照库独立实例**（PII），与 sign 财务库分离；KMS 静态加密。
- **events 流水表按月分区**（事件溯源、量大、可归档）；高频查询字段建索引（passport_no、room_id、timestamp）。
- 连接池统一管理；只读副本承接报表/看板查询，避免压主库。
- 迁移用版本化 migration（可回滚），纳入 CI。

### 2.2 对象存储（OSS）

- **私有桶**，按环境分桶；目录规划 `{env}/{yyyy-mm}/{room_id}/{msg_id}.{ext}`。
- 服务端加密（SSE/KMS）；**禁公共读**；访问用临时签名 URL（短时效）+ RAM 授权，不生成长期公开链接。
- 图片去重以内容 hash 为对象键的一部分。
- 生命周期规则：热数据标准存储 → 冷数据低频/归档 → 到期删除（见 §四 留存）。

### 2.3 缓存 / 队列（Redis Tair）

- Redis Stream 做消息队列 + 消费组（at-least-once，幂等消费）。
- 去重集合（消息指纹）设 TTL。
- 开启持久化（AOF）；积压监控告警。

### 2.4 数据分级与保留

按 [04 §一](04-合规与数据安全规范.md) 分级；保留期、删除、按护照导出/删除能力在此落地为 OSS 生命周期 + DB 归档作业。

## 三、备份与容灾

| 目标 | 指标 | 手段 |
|------|------|------|
| RPO（可容忍丢失） | 【待定】≤ ___ | RDS 自动备份 + binlog；OSS 版本化 |
| RTO（恢复时长） | 【待定】≤ ___ | 快照恢复 + IaC 重建 |

- **RDS**：自动备份 + 定期手动快照；保留期满足审计要求；跨可用区高可用。
- **OSS**：开启版本控制（防误删/覆盖）；重要数据跨区复制。
- **会话存档 5 天时效兜底**：拉取服务故障期间数据会过期丢失 → 拉取服务必须高可用 + seq 落后告警（见 §九）；这是本系统**最脆弱的数据点**，备份救不了"没拉下来的"。
- **恢复演练**：定期演练从备份恢复（每【待定】季度一次），验证 RTO/RPO 真实可达，而非纸面。

## 四、审计（财务 + PII 双重要求）

审计是本项目的硬需求，分四类，全部不可篡改、留存满合规期：

1. **业务审计**：事件溯源（events 只追加）天然提供"每条数据怎么来的"全链路，可重放。
2. **PII 访问审计**：谁、何时、为何 读取/导出 完整护照号/姓名/护照图 → 独立审计日志。
3. **数据变更审计**：审核人对抽取结果的每次修改（旧值→新值→操作人→时间）。
4. **操作审计**：登录、权限变更、配置变更、删除操作。

要点：审计日志**写入只追加/WORM 存储**，与业务库分离；敏感值在审计中也脱敏，必要时加密留存；提供按客户/时间段的审计检索。

## 五、可观测性

- **日志**：结构化 JSON + 全链路 trace id（一条消息从采集到入库可串起）；敏感字段脱敏；集中采集（如 SLS）。
- **指标（Metrics）**：消息吞吐、漏斗各级命中率、抽取置信度分布、审核队列长度、企微拉取 seq 落后量、API 调用量/成本/延迟、队列积压、错误率。
- **链路追踪（Tracing）**：跨服务调用链，定位瓶颈。
- **看板 + 告警分级**：P1（数据可能丢失，如拉取停摆）即时通知；P2（准确率/积压异常）；P3（成本/容量预警）。告警要有 on-call 接收人。

## 六、安全基础设施

- **网络**：VPC + 子网分段（拉取服务/处理/数据库分层）；安全组最小放行；数据库不暴露公网；拉取服务固定 EIP（企微白名单）。
- **身份与权限**：RAM 子账号/角色最小权限；处理服务、审核后台、运维各自角色；护照完整值仅必要角色可读。
- **密钥**：KMS 托管；RSA 私钥、企微 secret、百炼 AK/SK、库口令全部 KMS/环境变量，定期轮换；绝不入库入 git。
- **运维通道**：堡垒机/跳板访问生产，操作留录。
- **应用安全**：依赖漏洞扫描（CI 内）、密钥泄露扫描；若审核后台对外暴露，加 WAF + 认证 + 速率限制 + CSRF。
- **数据脱敏**：日志、看板、审核列表默认脱敏，完整值受控展示并审计。

## 七、CI/CD 与发布

- **流水线**：lint → 类型/构建 → 单元/集成测试 → **385 离线回归（准确率守门）** → 安全扫描 → 部署。任一环节失败阻断。
- **测试门禁**：覆盖率 ≥80%；385 回归准确率不得低于基线。
- **发布策略**：灰度/蓝绿；按代理/群分批放量；一键回滚。
- **IaC**：云资源（ECS/RDS/OSS/VPC/RAM）用基础设施即代码管理，可重建、可审计、环境一致。
- **配置与代码分离**：404 群配置、规则字典、阈值独立管理，支持热更新优先。

## 八、容量与伸缩

- **峰值估算**：404 群 ≈ 2–8 万消息/天；候选图 ≈ 1.5–2 万/月。
- **worker 弹性**：LLM worker 按队列积压伸缩（I/O 密集，可高并发）；可选函数计算承接突发。
- **限流与退避**：遵守企微（拉取 ≤4000 次/分、≤1000 条/次）与百炼配额；失败指数退避，不丢消息。
- **背压**：队列积压超阈值告警并降级（优先保关键群）。

## 九、高可用

- **拉取服务**：本系统单点风险最高处。需主备/健康检查 + 自动拉起；seq 断点续拉；**落后告警**（5 天时效，落后即数据丢失风险）。
- 无状态服务多实例 + 负载均衡；数据库跨可用区。
- 健康检查与自愈；关键依赖（百炼/企微/OSS）故障时降级策略明确。

## 十、SLA / SLO

| 指标 | 目标（待定） |
|------|--------------|
| 拉取时效 | 消息产生到落库 ≤ ___（远小于 5 天） |
| 抽取延迟 | 候选图入库到出结构化结果 ≤ ___ |
| 服务可用性 | ≥ ___% |
| 错误预算 | 超出触发止血与复盘 |

## 十一、成本治理

- 用量监控 + **预算告警**（API/云）；模型成本按群/代理/任务归因，定位浪费。
- 漏斗纪律（MRZ 免调、hash 去重、便宜模型分类、降分辨率）持续优化单位成本。
- 定期出成本报表，纳入 §10 错误/成本预算治理。

## 十二、数据治理

- **主数据**：护照号为客户主数据，统一口径；中英术语字典维护在 config。
- **数据质量**：抽取置信度、字段完整率、对账差异率作为质量指标监控。
- **血缘**：事件溯源 + trace id 提供从原始消息到对账结果的血缘，可回溯。

## 十三、运维 Runbook 与事件响应

- 常见故障处置手册：拉取停摆、队列积压、API 配额耗尽、审核积压、密钥轮换。
- 故障分级 + on-call + 复盘（事后改进项回流到风险登记册）。
- 上线/回滚 checklist；定期容灾演练（§三）。
