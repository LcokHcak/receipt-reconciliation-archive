# 02 · 架构与技术栈

## 一、设计原则

1. **采集层适配器隔离**：唯一的"脏活/易变"层，做成可替换接口；企微存档与 wxauto 输出同一消息格式，上层不感知来源。
2. **表达层 / 业务层分离**：LLM 吸收消息形式的混乱（表达层），状态机保证业务规则的统一（业务层）。代理差异 → 一行配置。
3. **先落库再处理**：原始消息与图片永远先原样存下，处理逻辑可随时改了重跑。
4. **事件溯源**：events 表只追加，state 可由事件重算 → 可重放、可审计。
5. **配置驱动**：404 群配置是数据不是代码，新代理 = 加一行。
6. **护照号为主键**：一切归组与对账围绕护照号展开。

## 二、八层架构

```
①采集层    企微会话存档 SDK（主） / wxauto（备）  → 统一适配器
   ↓ HTTPS / 内网
②接入层    Node + Express · 原始落库 · 图片入 OSS · hash 去重
   ↓
③队列层    Redis Stream + worker 池（削峰、异步、可重放）
   ↓
④理解层    漏斗：规则预过滤 → 轻量分类(Qwen-Turbo) → 多模态抽取(Qwen-VL-Max) + MRZ解析
   ↓  （输出标准业务事件 JSON）
⑤编排层    状态机（护照生命周期） + 分组引擎（护照号/航班号/姓名）· 事件溯源
   ↓
⑥数据层    PostgreSQL：客户(护照PK) → 团号(1:N) → 小票 + 航班 + events流水
   ↓
⑦应用层    审核后台（低置信转人工·预填候选） + 截止日告警（催缺票）
   ↓
⑧集成层    按数据契约交付 → sign（账单匹配 · 返点核算）
```

配置表（数据，横贯各层）：404 群 / 213 代理 / 群类型 / 店铺·团种·渠道 / 规则字段 → 驱动 ①路由、④prompt 选择、⑤状态机规则。

## 三、采集适配器契约（统一消息格式）

所有采集来源必须产出以下统一结构，写入接入层：

```jsonc
{
  "source": "wecom_archive | wxauto",   // 来源，仅采集层关心
  "msg_id": "全局唯一",
  "room_id": "群标识",
  "room_name": "群名（企微需用 roomid 换取）",
  "sender_id": "发送者标识",
  "sender_name": "发送者群昵称",
  "timestamp": "ISO8601",
  "msg_type": "text | image | file | revoke | system | ...",
  "text": "文本内容（如有）",
  "media_ref": "图片/文件在 OSS 的引用（如有）",
  "quote_msg_id": "被引用消息ID（如有，归组重要信号）",
  "fingerprint": "发送者+时间+内容hash，用于跨账号去重"
}
```

### 企微会话存档拉取服务（主路径）

```
企业微信(云端存档)
  │  libWeWorkFinanceSdk_C.so（C SDK，Node/Python 可调）
  ▼
拉取服务(Linux ECS, 常驻, 固定公网IP)
  ① 按 seq 翻页拉密文（首次 seq:0，≤1000条/次，≤4000次/分）
  ② RSA 私钥解出 AES key → 解出消息明文 JSON
  ③ 媒体消息用 sdkfileid 下载 → 存 OSS
  ④ 记录最新 seq（断点续拉） + roomid 换群信息
  ⑤ 映射成统一消息格式 → 接入层
```

要点：5 天时效 → 高可用 + 落后告警；可信 IP 白名单；公钥后台填、私钥自留。

## 四、理解层（LLM 漏斗）

| 级 | 处理 | 模型/手段 | 成本 |
|----|------|-----------|------|
| 0 规则预过滤 | 白名单代理、丢系统/表情、图片 hash 去重 | 代码 | 0 |
| 1 轻量分类 | 判意图：挂团/团号/小票/护照/行程/催收/账单/闲聊 | Qwen-Turbo | 极低 |
| 2 多模态抽取 | 仅候选图：护照、小票、行程字段抽取 | Qwen-VL-Max | 大头 |
| 2' MRZ 解析 | 护照机读码两行 → 护照号/姓名/有效期 | npm `mrz` | 0 |

- 输出 **JSON Schema 强约束**，含 `confidence` 置信度。
- **会话窗口聚合**：同一发送者数分钟内连发的消息合并为"提交单元"再送 LLM（解决裸数字团号、护照小票分开发等上下文依赖）。
- 低置信 → 人工审核队列。

### 标准业务事件（举例）

```jsonc
{"event":"REQUEST_GROUP","modes":["SG","H","PKG"],"evidence":"S-H-PKG 挂三个写一下哈"}
{"event":"ASSIGN_GROUP","group_no":"26144790","valid_until":"6/12","passport":"EN7296496","name":"SUN XIAO"}
{"event":"SUBMIT_RECEIPT","group_no":"26143139","store":"乐天明洞","amount":2579,"image_ref":"oss://..."}
{"event":"SUBMIT_PASSPORT","passport":"EM9314578","name":"BAI FANGRUIYAN","image_ref":"oss://..."}
```

## 五、数据模型（护照号为主键）

```
customers            客户（护照号 PK）
  ├─ passport_no (PK)  姓名、拼音、出生日期、护照图ref、所属群/代理
group_bindings       团号（1:N，一本护照挂多团）
  ├─ group_no、模式(SG/H/PKG..)、店铺、有效期、passport_no(FK)
receipts             小票
  ├─ 小票号、店铺、购买日期、品牌、数量、金额($/￦)、group_no、passport_no(FK)、image_ref、confidence
flights              行程
  ├─ 航班号、出发/到达、离境日期、passport_no(FK)、image_ref
events               事件流水（只追加，事件溯源）
  ├─ event_type、payload(jsonb)、source_msg_id、timestamp、confidence
review_queue         人工审核队列
  ├─ 待确认项、预填候选、状态、审核人、修正结果（回流为样本）
```

字段对齐 385 文件夹里 `账单.xlsx` 的「明细」表头：返点模式/分店/购买日期/团号/姓名/护照号/小票号/品牌/数量/总卖出($/￦)/纯卖出($/￦)/客人点数/返点金额。

## 六、分组引擎（如何判定"一组"）

按可靠度排序的连接信号：

1. **同框照片**（护照+小票一张图）→ 一张图即一组，最强。
2. **护照号 join**（全局主键）：护照图 OCR/MRZ 出护照号 = 小票上护照号 = 团号消息里护照号。
3. **航班号副键**：小票航班号 = 行程截图航班号 → 把无姓名的行程图焊入组。
4. **姓名校验**：护照名 ≈ 小票名（可能部分打码）。
5. **会话窗口 + 引用链 + 群=代理线**：群聊场景独有的辅助信号。

不依赖消息先后顺序；串不起来或低置信 → 人工审核，系统按"同代理+同日期+待收票护照"预填候选。

## 七、状态机（护照生命周期）

```
提交证件 → 申请挂团(SG/H/PKG..) → 员工回团号 → 客户购物 → 交小票 → 小票收齐 → 对账 → 返点
```

- 1 份状态机定义 × N 个实例，**按护照号建实例**（不是按代理）。
- "已挂团但小票未收齐" + 截止日规则 → 每天生成催收清单（告警）。

## 八、技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 主语言 | Node.js | 对齐 sign，复用工程习惯 |
| 采集器 | 企微存档 C SDK（Node 调 .so）；wxauto 备选（Python） | 跟工具生态走，隔离成适配器 |
| Web/API | Express | 同 sign |
| 队列 | Redis Stream（Tair） | 量级够用，免重运维 |
| 数据库 | PostgreSQL（RDS） | 事务、jsonb 事件存储、托管 |
| 图片 | OSS 私有桶 + 服务端加密 | PII 隔离、生命周期管理 |
| LLM | 阿里云百炼 Qwen（Turbo 分类 / VL-Max 抽取） | 国内合规、护照不出境、成本低 |
| MRZ | npm `mrz` | 护照机读码零成本解析 |
| 加密/权限 | KMS + RAM | PII 底座 |
| 部署 | ECS + pm2 / Docker | 同 sign 习惯 |

## 九、部署拓扑（阿里云）

```
[采集] 企微会话存档(云端) ──SDK──> 拉取服务(Linux ECS, 固定公网IP)
                                         │ 同 VPC 内网
   ┌─────────────────────── VPC（同地域）───────────────────────┐
   │  处理 ECS(Node·worker·审核后台)   现有 sign ECS             │
   │        │  内网调用                      ▲ 数据契约交付       │
   │   RDS PostgreSQL(护照库,独立,KMS)  Redis Tair   OSS(私有桶) │
   └────────────────────────────┬──────────────────────────────┘
                                 ▼ 内网/私网
                          阿里云百炼 Qwen API
```

- **验证期**：处理后端可暂挤 sign ECS；只额外开 OSS + 百炼 + 企微试用。
- **生产期**：拆独立处理 ECS + 独立 RDS（护照 PII 隔离）；同 VPC 内网互通。
