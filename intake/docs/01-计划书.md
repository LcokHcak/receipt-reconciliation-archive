# 01 · 项目计划书

## 一、背景与问题

韩国免税挂团返点业务中，代理、客户、财务在微信大群里沟通。代理用**不固定的形式**在群里发客户护照、小票、行程截图，财务靠人工在 Excel 里记账对账。

现状痛点：

- 群数量大（**404 个群、213 个代理**），人工收集小票/护照不可持续。
- 代理发消息**形式千差万别**，且夹杂大量与收票无关的业务与闲聊。
- 小票有**硬性截止日**，逾期无返点；漏收 = 直接经济损失。
- 客户信息（护照/小票/行程/金额）分散在消息流里，需要**归组成一个客户档案**才能对账。

目标是：在**代理完全不改变现有工作习惯**的前提下，自动完成采集、识别、归组、对账。

## 二、目标

### 业务目标

1. 自动从群消息收集护照、小票、行程，按客户（护照号）归组。
2. 对不同类型消息做不同业务处理（收票 / 挂团 / 催收 / 情报）。
3. 主动告警：已挂团但小票未收齐、临近截止日 → 防返点损失。
4. 结构化结果对接 `sign`，打通对账与返点核算。

### 技术目标

1. 采集层可替换（企微存档为主，wxauto 备选），上层不感知来源。
2. 表达层（LLM）与业务层（状态机）分离，代理差异降级为一行配置。
3. 全链路事件溯源、可重放、可审计（财务场景必需）。
4. 护照 PII 合规：加密存储、不出境、最小权限。

## 三、范围

### 本期做（In Scope）

- 业务群（279 个）的收票/挂团/催收全链路。
- 护照 MRZ 解析、小票字段抽取、行程关联、护照号归组。
- 审核后台、截止日告警、对接 sign 的数据契约。
- 404 群配置表解析与配置驱动路由。

### 本期不做（Out of Scope）

- 沟通群（皮肤科医美）业务线 —— 架构预留，后期按"加一组意图+handler"扩展。
- 点位群情报的深度结构化 —— 先落档存储，供查询，不做自动核算。
- 自动回复/自动发消息 —— 本系统只读不发，降低风险。
- 替代 sign 的对账逻辑 —— 复用现有 sign。

## 四、数据接入决策

**主路径：企业微信会话内容存档 API**（已确认采用）

- 官方合规、跑 Linux ECS、**无需单独 Windows 采集机**。
- 代理/客户继续用个人微信，通过微信↔企微互通进群，发言被存档。
- 约束（必须接受）：
  - 只能**向后采集**，拿不到开通前的历史；且只存 5 天，须定期拉取落库。
  - 群必须是**企微外部群**，由有"客户联系"权限的企微成员创建。
  - 客户入群有**存档告知**，不同意者会被移出群。
  - 需企业认证 + 购买会话存档许可（有 30 天试用）。
  - **系统全量上线节奏 = 企微迁移节奏**，无法抢跑。

**备选/过渡：wxauto 采集机**

- 若需在企微迁移完成前先跑实时链路，用 wxauto 多开顶上，输出同一消息格式。
- 仅作过渡，不承载长期生产。

**历史样本来源**：不依赖采集，用现成的 385 个客户文件夹真值集做离线验证。

## 五、里程碑

| 阶段 | 周期 | 内容 | 验收标准 |
|------|------|------|----------|
| **Phase 0 离线验证** ★闸门 | 第 1–2 周 | 用 385 文件夹跑识别+分组+成本 | 字段抽取准确率、分组准确率达标；实测单图 token 成本 |
| **Phase 1 采集+实时链路** | 第 3–5 周 | 企微存档拉取服务 + 接入 + 队列 + 理解层，灰度 2–3 群 | 实时消息落库、抽取、生成事件，端到端跑通 |
| **Phase 2 编排+应用** | 第 6–8 周 | 状态机 + 分组引擎 + 审核后台 + 截止日告警 + 对接 sign | 一本护照从挂团到入账全自动；低置信转人工；催收清单可用 |
| **Phase 3 全量铺开** | 第 8 周后 | 按代理分批接入全部业务群 | 受企微迁移进度决定，非代码决定 |

**可用 MVP ≈ 6–8 周**（半自动 + 人工兜底）。**全量上线**取决于企微迁移运营进度。

## 六、从哪里开始（首个动作）

**起点 = Phase 0 离线验证脚本，对象是 385 个客户文件夹。**

为什么从这里开始：

- **不依赖任何采集方式**，不必等企微，今天就能做。
- **一次性验证三件最大的不确定性**：LLM 能否准确抽字段、护照号归组是否可靠、单位成本到底多少。
- **真值现成**：文件夹名（姓名+护照尾号）与 `账单-客户名.xlsx` 就是标准答案，无需人工标注。
- 过了这道闸门，整个项目的核心技术风险基本解除，再投入采集与工程才划算。

首个动作的具体步骤：

1. 搭最小验证脚手架（Node + 百炼 SDK + `mrz` 库）。
2. 先拿 3–5 个文件夹试跑：每张图 → 多模态抽字段 → 护照号+航班号归组。
3. 与文件夹真值 / 账单 xlsx 对账，输出准确率报告 + token 成本实测。
4. 调 prompt 与分组规则，再扩到全部 385 个，形成基线指标。

## 七、并行轨（不阻塞 Phase 0）

企微会话存档开通（运营 + 配置）：

1. 企业认证 →「管理工具 → 会话内容存档」开通（先用 30 天试用）。
2. 生成 RSA 密钥对，后台填公钥；配置可信 IP（拉取服务器固定公网 IP）。
3. 用有"客户联系"权限的企微号建 1–2 个试点外部群。
4. 在试用期内把"SDK 拉取 → 解密 → 下图存 OSS → 落库"跑通。

## 八、角色分工

| 谁 | 做什么 |
|----|--------|
| 业务方 | 拍板数据接入决策；推进企微认证/许可/建群；提供群配置、员工白名单、团号规则、截止日规则；指定审核人 |
| 开发（含 AI 协作） | Phase 0 验证脚本；理解层 prompt + Schema；状态机 + 分组引擎；审核后台；对接 sign |

## 九、风险与卡点（按风险排序）

1. **采集稳定性**：企微存档 5 天时效 → 拉取服务必须高可用 + 落后告警；wxauto 备选受微信版本影响。
2. **模糊票/遮挡票分组**：无法 100% 自动 → 低置信进人工，系统预填候选。
3. **企微迁移长尾**：纯运营，决定全量上线时间，须尽早启动。
4. **跨账号去重**：多员工号同群收重复消息 → 消息指纹去重，需测干净。

## 十、成本预算（量级，非精确）

- **LLM API**（按 10 万条/月）：约 ¥1,000–2,000/月，优化后（MRZ 免调、hash 去重、便宜模型分类、降分辨率）可压到 ¥500 以内。
- **阿里云**：验证期处理后端可暂挤 sign，只额外开 OSS + 百炼，新增成本极低；生产期拆独立 ECS + 独立 RDS。
- **企微**：会话存档许可按席位/年（需向企微确认当期价格）。
- 对比价值：系统防住的逾期返点损失远高于以上成本。
